# Fable技術レビュー回答: Phase 2末見積り(d)進角・(e)周回横方向 — 判定

━━━ (d) 整流モデルの進角拡張 ━━━

【選択肢A/Bの物理判断】Aが正しく、Bは無効である。
根拠: 進角(brush advance)はブラシ取付角の回転であり、動くのは
「整流の切替タイミング」だけである。sinθが表す磁束鎖交は磁石と
ローターの物理的位置関係で決まり、ブラシをどこへ回そうと磁石は
動かない。よってsinθはθの生値のまま(A)。選択肢Bは切替点と磁束位相を
同量シフトするが、これはθ→θ−αの座標の付け替えにすぎず、コギング・
デッドゾーンとの相対関係を除けば進角ゼロと等価——「効果が出ない
実装」になる。

【ただし重大な発見】選択肢Aを現行の電気モデルへ入れても、spec §9.2の
「高回転寄り/トルク寄りの特性シフト」は原理的に再現できない。
現行モデルは無誘導(電流が毎瞬 (V−backEmf)/R で決まる記憶なしの
オーム的モデル)であり、この場合の進角αの平均効果を解析すると、
ストールトルクと無負荷回転数が共にcos α倍される**左右対称の純粋な
劣化**になる(切替直後の逆トルク区間が生じるだけで、どの速度域にも
利得がない)。実物で進角が高回転側の利得を生む機構は電機子
インダクタンスによる電流反転の遅れ(L/Rの時定数)であり、現行engineに
存在しない。つまりspecの約束を果たすには、進角フィールドの追加
(本見積りの中規模)に加えて**電流の一次遅れ(インダクタンス)の導入**
という、電気モデルの中核への実拡張が必要になる。これは
computeElectricalStateを記憶なしから状態持ちへ変える変更であり、
全回帰・性質テストに波及する。見積りの「中規模」は、spec要求を
満たす実装としては過小である。

【判定: §2(d)の降格条項を発動し、進角は将来枠へ降格することを
推奨する】
- spec §2(d)は「大規模なら進角は将来枠へ降格」とあらかじめ定めており、
  本件はその条項の想定どおりの帰結である
- 溝掘りジェスチャーはspec §9.2の予定フォールバックどおり
  「接触品質(チャタリング・D05)のみ」に接続してPhase 4を実装する。
  工作要素としての溝掘りは失われない
- 進角を入れるなら「インダクタンス導入+進角」を一体のパッケージと
  して将来(V3後期またはV3.x)に再見積りする。偽の非対称式(物理を
  装った速度依存ボーナス)で誤魔化す案は、本シリーズの流儀に反する
  ため検討対象にしない
- 版数論点は降格により消滅する。将来実装時は、確立済みの原則
  (版数=フィールド集合)に従いMC4-新設とする
- docs対応: spec §9.2の進角行への「将来枠(§2(d)発動、2026-07-23)」
  注記と§2(d)の状態更新を、Phase 2ゲートのdocs-only変更として人間
  承認に載せること

━━━ (e) 車両層の周回・横方向拡張 ━━━

【判定: 採用する。降格しない】周回コースはV3の中核仕様(§6.5、人間
承認済みの企画判断)であり、(d)のようなフォールバックは存在しない。
「中〜大規模」の再評価は妥当として受け入れ、代わりに実装を分割する。

【分割指示】Phase 5内で2つの独立ステップとする(alice所見の分割可能性
を採用):
- (e)-1 周回構造: 累積positionM+区間解決のmodulo化+目標ラップ数+
  終了判定。レースが成立する最小単位
- (e)-2 壁擦り+ローラー: 80〜100%域の抵抗力結合(4箇所)+ローラー
  2値写像。(e)-1の完成後に着手
各ステップは通常どおり実装前計画→Suu→Fable→人間承認を経る。

【個別論点の回答】
1. (b)lapsCompletedの表現: **導出方式を採る**(新規stateフィールド
   不要)。設計指針: positionMは累積のまま巻き戻さない(周回で
   wrapしない)。区間解決のみ positionM mod 周長 で行い、
   lapsCompleted = floor(positionM / 周長)、完走判定 =
   positionM ≥ 周長×目標ラップ数。浮動小数点は決定論的なので
   再現性は保たれ、境界のε問題は「周回切替の瞬間の表示」にしか
   影響しない(物理は連続なので影響なし)。状態を増やさない案が
   凍結方針と整合する
2. (a)符号付き曲率: **不要、符号なしを維持する**。V3仕様に左右
   非対称の車体特性は存在せず、保持判定は対称でよい。ただし俯瞰
   描画(art-spec §5.1.1)はコースの左右形状を必要とするため、
   Phase 5のコースデータ設計で「描画用の左右情報を持ち、engineは
   それを読まない」構造にする(表示情報を物理へ混ぜない)
3. (c)壁擦りの数式は実装計画の責務でよいが、設計制約を1つ先に
   固定する: 抵抗力は比率0.8の閾値で**連続**であること(閾値で力が
   不連続に立ち上がる式は積分の安定性と決定論的な挙動の滑らかさを
   損なう。0.8超過分に比例するランプ形が自然)。火花演出用の
   比率出力(0〜1)をVehicleSimStateへ含める案は承認
4. (d)ローラー2値(保持ボーナス+転がり抵抗損)の設計と、写像を
   materialMapping.tsに閉じengineはローラー材質を知らない構造:
   承認。設計較正値の規律(Recordテーブル+根拠コメント)を踏襲する
5. (e)質量配分合成の所有層: Phase 4/5計画時決定に同意。候補と
   しては「配置UIが搭載位置を選び、materialMapping系の純関数が
   centerOfMassHeightMm等へ合成する」二層(選択=UI、合成=写像層)が
   既存の役割分担と整合するが、確定はその時の計画で行う
6. 目標ラップ数はTrackDefinition(レース定義)側に持ち、レシピ
   コードには含めない(マシンの定義とレースの定義の分離)。
   recipeCodeへの影響なし、を確認した

【期待される創発の予告(実装計画・報告書用のメモ)】壁擦りが減速力と
して正しく結合されると、「限界超過気味でコーナーへ進入→壁擦りで
減速→保持域に戻って曲がり切る」という挙動が自然に創発するはずで
ある。これは実物のホビーレーサーの「壁走り」そのものであり、バグでは
なく仕様どおりの物理として歓迎する。(e)-2の試験項目に「壁擦りに
よる自己回復的なコーナリングが観測されること」を含めてよい。
