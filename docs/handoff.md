# 引き継ぎメモ(V1.0 → V1.5 → V2 → V3)

このドキュメントは、V3で新規参加するUI/描画/音担当エージェントが**30分程度で文脈を把握できる**ことを目標にまとめています。ルールそのものは `AGENTS.md`(`CLAUDE.md`と同内容)を、詳細仕様は `docs/spec.md`(V3唯一の正)・`docs/art-spec.md`(アート仕様、常時参照物)を参照してください。このメモ自体は正式仕様の代わりにはなりません。

**エンジン(`src/engine/`)の実装判断の詳細な経緯**は、要点のみ§2〜3に記載し、完全な導出過程は各`__tests__/`ファイルとgit履歴に譲ります(engine/への変更はaliceのみが行うため、UI担当はAPI契約の結果だけ把握すれば十分です)。

## 1. これまでの経緯

**V1.0**(「回れ!手作りモーター」、中学生向け): 実験室・調整チャレンジ・トラブル診断・組み立てモードの4モードを実装。中心方程式は`J·dω/dt = T_mag + T_fric + T_drag`。物理エンジンはReactに一切依存しない純関数(`step(config, state, dt, rng?)`)。

**V1.5**(「走れ!手作りモーターカー」への再定義、対象を中学生から大人へ): 線径・並列巻き・ワニス有無・コギングトルク・電池内部抵抗と発熱を追加。中学生向けヒント表示を廃止し、計測データをそのまま見せる方式へ転換。「答えを教えない、生の数値を見せる」という難易度哲学がここで確立した。

**V2**(「走れ!手作りモーターカー」、車体物理の追加): モーター単体から、ギヤ・車輪・車体・コースを含む車体層(`vehiclePhysics.ts`・`trackPhysics.ts`)を追加。反射慣性方式による連成、5コース、ガレージ、8工程のモーター工作、車体対応診断、実験ノート、車体込みレシピコード、実験室、音・演出・PWAを実装。Phase 0〜5が完了し、206テスト・build・lintが成功した状態で凍結(`docs/baseline-v2.0.md`)。

**V3**(「(仮題)挑め!手作りモーターカーGP」、現在地): V2エンジンを基盤に、在庫経済・実在素材ティア・破壊モードと失敗図鑑・実レシピCPUレース・レトロ描画パイプラインを追加する。V2のUI層(SVG描画・室内ジオラマ)は全面刷新するため移植しない。詳細は`docs/spec.md`。

## 2. 物理モデルの要点(V2から凍結継承)

- 中心方程式: `J_motor·dω_motor/dt = T_mag + T_cog + T_brush + T_drag − T_load`。整流子は角度θに応じて電流方向を反転(半回転ごと)、スリット幅から換算したデッドゾーン角度内ではトルクがゼロ。電流は逆起電力込みで`i = (V − e_back) / (R_coil + R_contact)`
- 車体層は**反射慣性方式**(`J_eff`)で非空転時を1自由度の拘束系として解く。空転時のみモーター側・車体側を2自由度に分離し、再結合時に総エネルギーを増やさない
- API契約: `motorPhysics.step()`は`evaluateMotorFrame`(電流・トルクの評価、rng条件付き消費)と`advanceMotorState`(`effectiveInertia`引数でJ_effを注入して積分)の二段構成。`vehiclePhysics.ts`は毎フレーム`evaluateMotorFrame`を1回だけ呼び、グリップ判定と積分の両方に使う。これにより車体層はモーター層の内部式(静止摩擦クランプ・チャタリング・軸ずれ振動等)を一切複製しない
- 空転/非空転は`state.isSlipping`を状態機械として扱う(前フレームの状態を必ず参照する。毎フレーム独立に再判定してはならない)
- 接地摩擦は相対すべりの符号に従う(`F_contact = sign(wheelSurfaceSpeed − velocityMps)·F_grip_max`)。常に前進方向固定ではない
- エネルギー保存の安全性担保は`energyBreakdown`(表示用5分類、厳密な代数収支は保証しない)とは別に、`E_total = E_mech + 重力PE`という不変条件(`E_total(t+dt) <= E_total(t) + 電池入力`)で行う
- 物理定数(`constants.ts`)は当てずっぽうではなく**設計目標から逆算**している。「もっともらしいから」で値を変えないこと

## 3. 既知の罠(要点のみ。完全な経緯は各`__tests__/`とgit履歴を参照)

1. **摩擦の符号とゼロクロス**: `T_fric`を無条件で引き算すると、ω=0通過時に摩擦自体が駆動力になり逆回転するバグになる。静止摩擦クランプと符号反転時のクランプの2段で防いでいる
2. **逆起電力とsin(θ)の整合**: `e_back`はT_magと同じ整流符号・角度を使わないとエネルギー整合性(`T_mag·ω = e_back·i`)が崩れる
3. **チャタリングは単発フレームでは効かない**: 瞬断を1フレームだけ発生させると慣性とRPM移動平均に埋もれて表示に現れない。`CHATTER_BURST_FRAMES`(24フレーム)でバースト化して初めて体感・評価に反映される。**「1フレームだけの確率イベント」は積分と平滑化を経て見た目には現れない**、という教訓は他の確率的挙動(V3の破壊モード等)にも適用される
4. **整流の回転方向は極性で決まる**: 弾いた向きに関わらず、最終的には正方向の定常回転に収束する(実物の2線整流子と同じ)。UIの直感設計に注意
5. **反射慣性の連成は別々に積分しない**: モーター軸と車体を別自由度で積分し補正トルクで追従させる方式は禁止。テストでしか気づけない数値的破綻を招く
6. **空転再結合でエネルギーを増やさない**: グリップ回復時に車速を不連続に変更しない。消えた回転エネルギーはタイヤの滑り損失として記録する
7. **押し出し始動の初速整合**: 車体への初速`START_PUSH_VELOCITY_MPS`とモーター初期角速度を拘束式で一致させる。1フレームだけの不整合は見た目に現れずテストでのみ検出できる

## 4. V3核仕様の要点(`docs/spec.md`参照。UI/描画/音担当が最初に読むべき部分)

- **巻線記録方式(§9)**: プレイヤーの円ドラッグ1周=1ターン。`{位置,腕,方向,張力}`を記録し、ローターの描画・物理写像・レシピ文字列・CPUライバル定義すべてがこの記録から導出される。成否二値の判定は持たない(QTE化の回避)
- **実在素材ティア(§4)**: 導線・エナメル被膜・磁石・ギヤ・電池・ブラシ・台紙をすべて実在素材でティア化。物性値はカタログ値に準拠し、バランス調整でも物性値自体は動かさない(価格・入手性で調整)。写像層(`materials.ts`+`materialMapping.ts`、Phase2)はaliceが実装
- **破壊モードと失敗図鑑(§7)**: D01(コイル崩壊)〜D10(鉄心短絡)。初回発生時に図鑑登録(リプレイ+検死レポート+報酬)。不可逆ダメージは「症状(必ず可視化)→自動差分検知→計測器での原因確定(任意・有償)」の三段開示に従う
- **在庫経済(§5)**: 素材・パーツは個体管理(恒久状態を持つ)。破産防止の3層セーフティネット(最低ティアは常時安価・サルベージ底値保証・賞金グラインド許容)
- **実レシピCPU(§6)**: CPUカーはレシピ+シードのみで定義し、プレイヤーと同一エンジンで決定論的に走る。スクリプトタイム・ラバーバンドは導入しない
- **レトロ描画パイプライン(§8)**: 低解像度Canvasへのネイティブドット描画(SVGからの全面刷新)。内部解像度はPhase 1で4案から確定。パレットは`palette.ts`一元管理でRGB直値禁止。詳細規約は`docs/art-spec.md`

## 5. 開発上の境界

- `src/engine/`: エンジンオーナー(alice)。UI・描画・音・データ: UI担当。マネージャー: Suu(実装しない)
- V2由来のUI・store・modes・dataはV3の完成形ではなく**凍結参考実装**。Phase 0では削除せず、Phase 1で新UIシェルが構築でき次第、論理単位で置換・削除する
- 画面・音に関わる判断は`docs/art-spec.md`を根拠とする。同書にない判断は独自解釈せず、agmsg経由でSuuに確認すること
- 通信はagmsg(チーム`MotorGameV3`)。レビュー条件・承認条件は要約せず全文中継する
