## 1. 位置づけ・スコープ

Phase 3ゲート(`docs/spec_1.md` §12「破壊基盤+失敗図鑑」)のうち、**UI側の画面構成・遷移・文言**部分に限定する。破壊モードの状態機械(`DestructionState`)・発火後物理(§7.1.1)・`RunOutcome`・劣化差分の算出はalice所有であり、本書では扱わない。

本書が対象とする論点(v2から継承・spec r2で確定した契約への追従):

1. 検死レポートは失敗図鑑の各D0x詳細画面へ統合する(単独画面にしない、v2から継承)
2. 破壊発生時のUI遷移は**終端モード**(D02発火・D03破裂・D04炎上・D09焼付き)でのみ走行を停止し、プレイヤーの決定操作後に図鑑詳細兼検死レポート画面へ遷移する。**非終端モード**(D01崩壊進行・D05スパーク・D06歯欠け進行・D07可逆熱ダレ)は走行中に症状・イベント通知のみ表示し、走行継続する(v3で新規追加、spec §7.1.1)

## 4. 画面構成・導線

`art-spec-r2.md` §5.4のハブ&スポーク構成「本棚 → 失敗図鑑 / 実験ノート」に従い、`gameStore.ts`の`mode`ユニオン型へ`'encyclopedia'`(失敗図鑑)を追加する(v2から継承)。

```
ガレージ(拠点)
  └─ 本棚 → 失敗図鑑一覧(mode: 'encyclopedia')
              ├─ D0xサムネイル(未発見はシルエット、D08は「Phase5未実装」枠)
              └─ 選択 → D0x詳細画面(検死レポート統合先、5節)
                          └─ 「実験ノートを見る」導線 → 実験ノート(既存ExperimentNotebook)

走行画面(testRun/course)
  ├─ 非終端モード発火(D01/D05/D06/D07可逆域) → 症状・イベント通知のみ表示、走行継続(6節A)
  └─ 終端モード発火(D02発火/D03破裂/D04炎上/D09焼付き) → 走行停止・症状表示のまま保持(6節B)
                  └─ プレイヤー操作「検死レポートへ」→ 原子的反映成功後、図鑑D0x詳細画面(初回は発見演出+報酬、6節B)
                                                            └─ 確認操作 → ガレージへ戻る(既定フロー)
```

- 図鑑一覧・D0x詳細は**すべて閲覧専用**(spec §7.2「二回目以降は登録済み表示のみ」)。購入・サルベージのような状態変更操作は持たない
- 走行画面からD0x詳細への遷移は、通常の図鑑一覧経由の遷移と**同一コンポーネント**を再利用する(初回か既知かはpropsで分岐、5節)
- 非終端モードの症状通知は走行画面のHUD領域内に留め、画面遷移は発生させない(engineの`DestructionState`イベントを購読して描画するのみ。UI側で「何フレーム経過したら遷移する」等の独自タイマー判定は持たない)

## 6. 破壊発生時の遷移フロー(v3: 終端/非終端で分岐)

spec §7.1.1の発火後物理表に基づき、モードを終端/非終端に分けて扱う。**UIは独自の閾値・独自の停止条件を持たず、engineが発行する状態遷移にのみ従う**(spec §7.1.1「破壊判定を行うのはエンジンのみ」)。

### 6-A. 非終端モード(D01崩壊進行・D05スパーク・D06歯欠け進行・D07可逆熱ダレ)

1. engineから該当`DestructionState`イベントを受信するたびに、走行画面のHUD領域へ症状表示(視覚差分・SE)を反映する。走行は継続する
2. 図鑑への初回登録・詳細画面への遷移は、**走行終了後**(通常のリザルト遷移、または後続の終端モード発火時)にまとめて扱う。走行中に図鑑詳細画面へ割り込み遷移させない
3. D07の不可逆域到達(三段開示対象)は走行終了後、通常のリザルト経由で図鑑登録・詳細画面遷移を行う(段階1の走行中症状はHUD上のみ、spec §7.3)

### 6-B. 終端モード(D02発火・D03破裂・D04炎上・D09焼付き)

1. **破壊発生**: engineが該当D0xの終端イベント(`RunOutcome`の終了理由)を通知した時点で、走行を物理状態に従って終了/停止する(engine側の停止判定に従うのみで、UI側が独自のタイムアウトで停止を判断しない)
2. **症状表示の保持**: 走行画面はその場で停止し、破壊演出と症状を表示したまま**自動では遷移しない**(時間制の自動遷移は不採用、v2から継続)
3. **決定操作**: プレイヤー操作「検死レポートへ」(仮ボタン文言、8節)を押すまで停止画面を維持する。Escapeやタイムアウトでの読み飛ばしは設けない
4. **原子的反映の確認**: 「検死レポートへ」操作を受けて、store側が5操作(個体劣化・破壊消費・図鑑初回登録・初回報酬・実験ノート記録)の原子的反映を実行する(P3-0契約、alice/store領域)。反映成功後にのみ図鑑詳細画面へ遷移する
5. **図鑑詳細画面への遷移**: 原子的反映成功後、当該D0xの図鑑詳細画面(5節)へ遷移する。初回発見時は報酬ブロックを表示し(受領済み)、既知の場合は報酬ブロックなしで表示する
6. **ガレージへ戻る**: 図鑑詳細画面での確認操作後は、既定フロー(現行の走行後リザルト→ガレージ遷移と同じ導線)でガレージへ戻る。図鑑一覧経由でこの画面を開いた場合は、確認操作は図鑑一覧へ戻す(遷移元を状態として保持、10節)

破壊がリタイア(コースアウト・走行失敗)ではなく**通常完走**の場合の既存リザルト画面フローには影響しない。

- 決定操作「検死レポートへ」・図鑑一覧のD0xサムネイル選択・詳細画面の「戻る」「実験ノートで比較を見る」は、すべてフォーカス可能なDOM要素(button等)としてEnter/Spaceで操作可能にする

## 10. Store所有境界・実装への留意点

- 図鑑の発見済みフラグ・報酬受領済み状態はP3-0契約でセーブスキーマ版として確定する永続化対象である(spec §7.5「store所有」)。本書はレイアウト・遷移設計のみを対象とし、永続化スキーマの詳細確定はP3-0完了後に別途行う
- **mode遷移元の保持方式(v2から継続)**: 走行画面からD0x詳細画面への遷移時に「遷移元(走行画面/図鑑一覧)」を保持し、確認操作の戻り先を分岐させる状態(6-B節6)は、画面コンポーネント内のローカルstateへ散在させず、`gameStore`側の明示状態(例: `encyclopediaReturnTo: 'garage' | 'encyclopediaList'`のような単一フィールド)として持たせる案を優先する
- **原子的反映の呼び出し境界(v3新規)**: 6-B節4の原子的反映呼び出しは、UIコンポーネントから直接複数のstore更新関数を連続呼び出しする方式を取らない(spec §7.5「単に複数のZustandsetを連続実行する方式は不可」というSuu_mot3レビューの指摘はalice/store領域の設計指針だが、UI側の呼び出し方にも影響するため明記する)。UI側は単一の呼び出し(例: 単一のstoreアクション)を叩き、その成否(成功/失敗)のみを受け取って遷移を分岐させる設計とする。呼び出しの内部実装(トランザクション方式)はP3-0契約側で確定する
- `src/materials/`・`src/engine/`は変更しない(alice領域、越境しない)

## 11. テスト方針(実装時)

- 図鑑一覧: 未発見/発見済み/D08専用枠の表示分岐テスト
- D0x詳細画面: 初回(報酬ブロックあり)/二回目以降(報酬ブロックなし)の表示分岐テスト
- **非終端モード**: 症状表示中も走行が継続し、画面遷移が発生しないことの回帰テスト(6-A節)
- **終端モード**: 「検死レポートへ」操作前は自動遷移しないことの回帰テスト(タイマー等で時間経過させても画面が変わらないことを確認)
- **原子的反映失敗時**: 反映が失敗した場合に図鑑詳細画面へ遷移しないことのテスト(6-B節4)
- 熱ゲージ表示: 「未較正」と「未計測」が異なる入力(ゲージ値あり/取得不能)で正しく出し分けられることのテスト
- 遷移元による戻り先分岐(走行画面経由→ガレージ、図鑑一覧経由→図鑑一覧)のテスト
- キーボード操作(Tab/Enter/Space)・タッチ操作それぞれで一連の遷移が完走できることのテスト(横画面・縦画面の両方)
