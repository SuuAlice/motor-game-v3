## 第一条: 誇張スケール規則

**絵は実寸に忠実な写生ではなく、読み取りやすさ優先の模式図である**(回路図と同じ態度)。真の数値は計測パネルが持つ。絵の責務は「差が見えること」。

1. **可読性の単調性**: ゲームプレイに影響するパラメータ差は、どんなに小さくても必ず異なるドット表現を持つこと。「0.4mmと0.5mmが同じ絵」を禁止する
2. **線径**: 表示ドット幅 = `1 + round((d_mm − 0.2) / 0.1)` を初期式とする(0.2mm→1px、0.4mm→3px、0.6mm→5px)。実比率より誇張されるがこれは仕様
3. **コイルの膨らみ**: 巻数・整列度による断面の膨らみは実寸比の約3倍で誇張。乱巻きは輪郭の凸凹で表現
4. **劣化の可視化**: ブラシは摩耗量に応じて短く描く。被膜ダメージ蓄積はコイル表面のまだら(パレット1段暗い色の点在)で表現。減磁は**見た目に出さない**(spec §7.3の三段開示に従う——見た目で分かったら診断ゲームが壊れる)
5. **色+形の二重符号化**: 素材の判別を色だけに依存させない(色覚多様性対応)。磁石は色+形状(フェライト=角ブロック、アルニコ=馬蹄/棒、サマコバ=小さい角、ネオジム=薄い円盤)、線材は色+線幅表現で判別できること

## 2. 描画基盤

### 2.1 解像度と拡大

- **二層解像度規則(Phase 1では非規範・未実装、将来再検討時の設計メモ)**: 画面をワールド層(走行・ガレージ・マシン・背景・パーティクル)とUI/テキスト層(計測パネル・ノート・図鑑・カタログ・HUD文字)に分離してよい。ただしUI層は**ワールド層のちょうど2倍の解像度・同パレット・同フォント様式**に縛る(混合グリッドの違和感を抑えるための制約)。本作は「生の数値を見せる」流儀ゆえレトロゲームとしては文字量が多く、文字の可読性だけを外科的に上げるのがこの規則の目的だった。**Phase 1の4案比較(下記)でこの二層構成(候補c)は不採用となったため、本節は本番の要件ではない**。将来、UI可読性の外科的な引き上げが再び必要になった場合の設計メモとして残す
- 内部解像度は**480×270単層に確定した**(Phase 1、2026-07-22人間承認)。比較した4案:
  - (a) 320×180 単層 / **(b) 480×270 単層(採用)** / (c) ワールド480×270+UI層960×540(比較用・不採用) / (d) 640×360 単層
  - 比較題材: **巻線記録の乱巻き軌跡**(150ターンが潰れず「良い汚さ」に見えるか)・**ガレージ一枚絵**(描き込み密度)・**検死レポート画面**(文字密度。文字問題は絵の題材だけでは発見が遅れるため必須)
  - 判断基準・比較結果・採用理由の詳細は`docs/phase1-resolution-comparison.md`を参照
- 表示: ニアレストネイバーで**整数倍拡大のみ**。`ctx.imageSmoothingEnabled = false` を全コンテキストで設定。端数はレターボックス(N0色)で埋める。(二層構成不採用のため、ワールド層とUI層の拡大率連動は本番では適用外)
- スマホ縦画面: 内部解像度を縦持ち用に転置(横480×270を転置した単層270×480)したレイアウトを用意する。横画面と同一パレット・同一部品描画を使う

### 2.2 ピクセル規律

- 描画座標は常に整数ピクセル。サブピクセル描画禁止(例外は§7.5のMode 7層)
- **色演算は許可リスト方式**(スーファミのカラーマス相当)。許可される用途と演算のみ使用可:
  - 加算合成(発光): 火花・炎のコア・ヘッドライト・CRT計測画面のにじみ
  - 50%平均合成(半透明): 煙の希薄化・霧・ガラス・夕景/夜景の空気遠近(遠景レイヤに一律適用)
  - 画面全体のフェードイン/アウト、§9のCRTフィルタ
  - 上記以外の半透明表現は従来どおり市松ディザ(1px checker)で行う。**許可リストへの追加は承認事項**
- グラデーション禁止。階調はパレット内のランプ(§3)+ディザで表現
- 回転は**16方位スナップ**で描く(自由角回転はドットが崩れるため禁止)。車輪・整流子などの回転体は方位ごとに手続き再描画。例外は§7.5のMode 7層(演出専用のラスタ変換)
- カメラスクロールも整数ピクセル単位(サブピクセルスクロールはドットのチラつきを生む)

### 2.3 手続き描画の原則(パラメトリック連動)

スプライト画像ファイルは原則作らない。部品はすべて**構成値を引数に取る描画関数**として実装する:

| 部品 | 引数(例) | 見た目への連動 |
|---|---|---|
| コイル(巻線) | **巻線記録**(全ターンの位置・腕・方向・張力、spec §9.1) | 記録から軌跡を再構成して描画。1ターン=1折れ線。マシンごとに唯一無二の見た目になる |
| 台紙(短冊) | 素材(段ボール/プラ板/ベーク板)、高回転時のたわみ量 | 断面質感(段ボールは波形中芯)・走行中のしなり表現 |
| 車輪 | 径、素材 | 円の大きさ・色 |
| 磁石 | 素材、形状 | §第一条5の色+形 |
| ギヤ | 歯数、素材 | 歯の刻み数・色 |
| 電池 | 種類、膨張度(D03/D04) | 形状・膨らみ変形 |
| ブラシ | 素材、摩耗量 | 色・長さ |
| ボディ(外装) | 素材、塗装(塗装バンク)、肉抜き穴の配置、クリア窓 | 3/4視点の外形。クリアボディは窓から巻線記録が透ける(クローズアップ時)。肉抜き穴の配置は手癖として見た目に残る |
| ガイドローラー | 位置、数、素材 | マシン四隅の小円。壁擦り時に火花の発生点になる |
| 整流子(爪楊枝軸) | 溝位置(進角)、溝仕上げ | 溝の角度位置・エッジの粗さ(粗いと火花D05が出やすい見た目の根拠になる) |
| 台座(段ボール) | 軸受け穴の精度 | 穴の楕円度・マシンの傾き。ガタが大きいほど走行スプライトの縦揺れに反映 |

- 描画関数はエンジンの状態を読むだけで、状態を持たない(演出専用ステート禁止、spec §8.5)

## 3. マスターパレット(スーファミ級体制: コア32+拡張16+会場サブパレット16)

**コード内でRGB直値の使用を禁止する。** 全描画はパレット名参照とし、定義は `palette.ts` の1ファイルに集約する。Phase 1の試作画面で検証後に凍結し、以後の色追加はSuu経由の承認事項とする。

パレットは三層構成(スーファミのBG/OBJパレット方式に倣う):

1. **コア32色**(下表): 全シーン共通。UI・マシン・パーツ・パーティクルはこの範囲で描く
2. **拡張16色**(中間調・夕景・自然。§3末尾の表): ランプの段数を深くし、背景の階調表現に使う。全シーン共通
3. **会場サブパレット16色/会場**: 各会場(§5.1)が固有に持つ枠。会場テーマの固有色(畳の色、庭の緑の変種等)はここに定義し、シーン切替でロードする。定義は会場実装時にSuuの承認を経て `palette.ts` に追記

同時に画面に存在しうるのは最大64色(48共通+会場16)+塗装バンクの登場マシン分。

## 5. 画面様式

### 5.1 世界観と会場カタログ(2.5D背景)

世界観は**卓上世界**(確定): 手作りマシンが走るのは家と身の回りであり、会場は住まいの各所。「巨大な日用品の間を小さなマシンが駆ける」スケール感は、俯瞰視点では**床面の質感と巨大な小物の遮蔽**で表現する。会場ごとにG0床面とG3高所オブジェクトのテーマを差し替える。コース自体は全会場共通の「自作壁コース」様式(段ボール壁・工作材)で、家中にコースを組んだという世界観の原点表明を兼ねる(spec §6.5)。

| 会場 | 想定レース種別(spec §6.4) | 会場テーマ(G0床面/G3高所の内容) |
|---|---|---|
| 工作机サーキット | テクニカル/チュートリアル | 棚のシルエット、工具・ペン立て・スケール比の巨大な文具 |
| 廊下ストレート | スプリント | 木目床の光沢、障子・ドア・柱時計 |
| 階段スロープ | ヒルクライム | 段差の反復、手すり、窓からの斜光 |
| 縁側〜庭 | 耐久 | 植木・飛び石・物干し。屋外光 |
| 模型店ジオラマ(特設) | ボス戦 | 陳列棚、ショーケース、値札(文字は架空店名のみ) |

- **時刻変種**(昼/夕/夜)は G0床面・G3高所の色の組替え+画面全体の空気遠近(50%合成、§2.2)で作る(パレット内の割当変更のみ。色の追加はしない)。夜会場+ヘッドライト(加算合成)は耐久の演出枠
- 各会場のレイヤ構成は§5.1.1の俯瞰走行ビュー規約に従う

#### 5.1.1 俯瞰走行ビュー規約(3/4見下ろし)

走行画面は**俯瞰斜め(3/4見下ろし)の観戦カメラ**(spec §8.4)。周回コース(spec §6.5)の全形・ライン取り・コーナー挙動が読めることを最優先する。

| レイヤ | 内容 |
|---|---|
| G0 床面 | 会場の床(木目・畳・机上・土)。会場テーマの主舞台。等速スクロール |
| G1 コース | 自作の壁コース(段ボール壁・工作材・マスキングテープのライン)。壁は3/4視点の立ち上がりで描き、高さ2〜4px |
| G2 走行体 | マシン・破片・パーティクル。マシンは16方位スナップ(§2.2)の3/4視点手続き描画 |
| G3 高所 | 机の脚・観葉植物・家具など背の高いオブジェクト。マシンを一時的に隠してよい(遮蔽が俯瞰の奥行き表現)。わずかな視差(1.1倍)を許可 |

- カメラ: 自機追従スクロール(整数ピクセル)。コーナー進入時もカメラ回転はしない(コースが回るのではなくマシンが曲がる——ドット規律の維持と観察性のため)
- 奥行き表現はパララックスではなく**遮蔽と影**で作る: マシン・壁・家具は1pxの接地影を持つ
- **マシンの描き分け**: レース中のマシンは小サイズ(目安24〜32px)のため、ボディ塗装色+クリアボディの窓ハイライト(T1色)までを表現の限界とする。**モーターの見える格好よさはクローズアップの受け持ち**——リザルト・観察画面(spec §6.2)・図鑑リプレイでは大サイズ描画(96px級)を用意し、クリアボディ越しの巻線記録・回転する釘・火花を見せ場にする
- ミニマップ: コース全形κ(s)の縮小描画+マシン位置ドットをHUD隅に常置(周回レースの観戦に必須)

### 5.2 計測パネル・HUD

- HUDは7セグ数値+最小限のアイコン。走行中の常時表示は速度・電流・温度バーの3つまで
- 性能低下アイコン(spec §7.3-1の下矢印)はY1、点滅は4フレーム周期
- ガウスメーター等の計測器画面は単色CRT様式(G2 on N0、走査線風の1pxディザ)
- 実験ノート/図鑑はN6地に暗色文字の「紙」様式(レトロ攻略本の趣)

### 5.3 ガレージ(組み立て)

- 工程ステップUIはV2の構成(工程n/8表示)を踏襲しつつドット様式に翻訳
- **正典機(チュートリアル機)は理科教科書の伝統構成**——段ボール台座・爪楊枝軸・鉄くぎ電機子——で描く(spec §9.1)。段ボールの断面(波形の中芯)、爪楊枝の木肌、釘の頭など、素朴な素材感をドットで丁寧に拾うこと。卓上世界(§5.1)との質感の連続性を最優先する
- **巻線ビューはローターの側面図**(ユーザースケッチの構図: 水平の短冊+中央に垂直の爪楊枝+沿わせた釘): プレイヤーが円ドラッグで巻くたび、軌跡が1本の折れ線としてその場に積まれていく。描画は巻線記録(spec §9.1)からの再構成であり、**プレイヤーの手癖の乱雑さがそのまま絵になる**
- 乱巻きの「良い感じの汚さ」の描き分け規則: 1ターン=1折れ線、新しいターンほど手前(明色)、古いターンは1段暗色に沈める。逆巻きターンも**色では区別しない**(見た目でほぼ分からないからこそ診断題材になる、spec §9.2)。交差密度が解像度でつぶれないかはPhase 1比較の主題材
- **整流子工程(溝掘り)は軸端面の拡大ビュー**で行う: 爪楊枝の断面円に対して溝の角度位置が見える構図。進角の基準線(釘の軸方向)を薄く表示し、掘った溝とのなす角が読み取れること——分度器は出さない(答えを教えない流儀。角度の数値は計測パネル側)

### 5.4 シーンフロー(画面構成)

ガレージとレース会場は**別シーン**とし、ガレージを拠点とするハブ&スポーク構成:

```
タイトル
  └─ ガレージ(拠点・一枚絵ハブ)
       ├─ 机     → 組み立て(工程UI・§5.3)
       ├─ 棚     → 在庫・サルベージ
       ├─ カタログ → ショップ(§5.5)
       ├─ 本棚   → 失敗図鑑 / 実験ノート
       ├─ ドア   → 会場選択(家の見取り図) → レース → リザルト → ガレージへ戻る
       └─ ラジオ → 設定(音量・CRTフィルタ)
```

- ガレージ拠点は**クリッカブルな一枚絵**(ドット絵の室内。机・棚・本棚・ドアが各モードの入口)。歩行キャラによるRPG式移動は採用しない(人物なし規約 spec §8.8/コスト)
- 会場選択は**家の見取り図**様式(俯瞰の間取り図に会場アイコンを配置)。卓上世界の地図表現を兼ねる
- 一枚絵ハブはV3で最も「描き込み」が要る画面。Phase 1の解像度試作の題材はコイル巻き画面とこのガレージ一枚絵の2点とする(描き込み密度の検証を兼ねる)

### 5.5 ショップ様式

- ショップは**パーツ通販カタログ**様式とする: §5.2の「紙」UI(N6地・暗色文字)で、レトロホビー雑誌の通販ページ風に商品を並べる。注文→即時納品
- 店主キャラクターを置かないため、人物なし規約(spec §8.8)と自然に整合する
- 商品欄は写真枠(部品の手続き描画)+品名+物性抜粋+価格。**物性値の表記は計測パネルと同一の実単位**(カタログスペックの提示であり、実測との突き合わせはゲーム側の題材、spec §4)
- 未解禁ティアは「取扱予定」としてシルエット掲載(欲望の可視化)。解禁条件はボス名で示す

## 6. 破壊演出(パーティクル規約)

パーティクルはすべて手続き生成。**色はパレット名参照のみ**(RGB直値禁止、spec §14)。

| 種類 | 色遷移 | 寿命 | 挙動 |
|---|---|---|---|
| 火花(D05等) | Y1→M3→N3 | 8〜20f | 重力小、直線飛散、1〜2px |
| 煙(D02段階) | 白N5→灰N3→黒N1(過熱進行で遷移) | 40〜90f | 上昇+横流れ、市松ディザで希薄化 |
| 炎(D02/D04) | Fランプのパレットサイクル(4f周期) | 燃焼中持続 | 上方へ揺らぎ |
| 破片(D06/D08) | 素材色 | 30〜60f | 重力+バウンド1回 |
| 線材の暴れ(D01) | M1 | 破壊中持続 | コイルから伸びる折れ線を毎フレーム乱数振動 |

- 画面シェイクは最大3px・12フレーム以内(D03/D04/D08のみ)
- 同時パーティクル上限を定数化(`PARTICLE_MAX`、初期256)し、超過時は古いものから消す

## 7. アニメーション時間規律

- ロジックは60fps、スプライトアニメは**12fps格子**(5フレーム毎)に載せる。中割りのヌルヌル動作はレトロ様式から浮くため禁止
- 回転体(車輪・整流子)は回転数に応じて16方位を進める。高回転では「回って見えない」表現(残像リング)に切替
- モーター音は§8の規約に従う(サンプルの連続ピッチシフト。音は演出でなく計測情報の一部)

### 7.5 Mode 7層(疑似回転拡縮・演出専用)

スーファミの記号として、平面テクスチャの回転・拡縮・透視変形を行う専用層を1つ持つ。

- **用途は演出に限定**: 会場紹介の俯瞰カメラ、リザルトのリプレイ演出、会場選択(家の見取り図)のズーム・回転。**走行ビューは俯瞰斜め3/4見下ろしの通常Canvas描画**とし、Mode 7走行は導入しない(ゲーム性が変わるため)
- 実装は内部解像度のオフスクリーンに対する行単位のアフィン/透視サンプリング(ニアレスト)。ピクセル規律(§2.2)の整数座標・16方位制約はこの層に適用しない
- Mode 7層の上に通常スプライト(マシン・UI)を重ねられること

## 8. サウンド様式(サンプルベース・スーファミ級)

音源方針をファミコン的な矩形波直吹きから、**スーファミ的なサンプルベース**(SPC音源風)に格上げする。

- **全サンプル内製**: Web Audioの合成(オシレータ・ノイズ・FM的変調)でレンダリングした短サンプルのみ使用する。外部サンプルパック・実録音の既存素材は使用しない(spec §15の内製主義)。生成スクリプトをリポジトリに含め、サンプルは再生成可能に保つ
- **チャンネル規律**: BGMは8ch想定(SPC準拠の自主制約)。キック/スネア/ベース/コード/リード等をサンプル+エンベロープで構成し、シーケンサは自作(JSONの譜面データ)
- **残響**: ConvolverNode(自作インパルス応答)による軽いリバーブ。会場ごとに残響特性を変えてよい(廊下=長め、庭=短め——背景こだわりの音版)
- **モーター音**: 自作サンプルの連続ピッチシフトを回転数に直結。減磁・劣化の兆候が音程で聞こえること(spec §7.3-1)。診断情報としての音、の役割は音源方式が変わっても不変
- SE(火花・破裂・炎上・ギヤ欠け)はサンプル+ノイズ整形。破壊モードD01〜D09それぞれに固有SEを割り当てる
- 音量バランス・ミュートは設定(ガレージのラジオ)から。BGM/SE個別音量

## 9. CRTフィルタ(後段・任意)

- スキャンライン・湾曲・にじみは表示段の後処理シェーダとして**完全分離**。内部描画はフィルタの存在を知らない
- 設定でON/OFF、**デフォルトOFF**

## 10. 禁止事項(要約)

- RGB直値・パレット外の色 / **許可リスト(§2.2)外の色演算・アルファ使用** / 自由角回転(Mode 7層を除く) / サブピクセル(同) / スプライト画像ファイルの安易な追加 / フォント追加 / 外部サンプル・既存楽曲の使用(§8) / 実在製品の意匠・ロゴ・キャラクターの描画(spec §15) / 人物キャラクター(spec §8.8)
