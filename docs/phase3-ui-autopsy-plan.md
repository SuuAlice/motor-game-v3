## 4. 画面構成・導線

`art-spec.md` §5.4のハブ&スポーク構成「本棚 → 失敗図鑑 / 実験ノート」に従い、`gameStore.ts`の`mode`ユニオン型へ`'encyclopedia'`(失敗図鑑)を追加する(`'shop'`/`'inventory'`追加時と同じ拡張パターン、`docs/phase2-ui-shop-plan.md` §4踏襲)。実験ノートは既存`ExperimentNotebook`コンポーネント(現状`utilityPage`によるオーバーレイ表示、`App.tsx`)の系譜を維持し、本棚からの導線を実験ノートへも張る。

```
ガレージ(拠点)
  └─ 本棚 → 失敗図鑑一覧(mode: 'encyclopedia')
              ├─ D0xサムネイル(未発見はシルエット、spec §7.2)
              └─ 選択 → D0x詳細画面(検死レポート統合先、5節)
                          └─ 「実験ノートを見る」導線 → 実験ノート(既存ExperimentNotebook)

走行画面(testRun/course)
  └─ 破壊発生 → 走行停止・症状表示のまま保持(6節)
                  └─ プレイヤー操作「検死レポートへ」→ 図鑑D0x詳細画面(初回は発見演出+報酬、6節)
                                                            └─ 確認操作 → ガレージへ戻る(既定フロー)
```

- 図鑑一覧・D0x詳細は**すべて閲覧専用**(spec §7.2「二回目以降は登録済み表示のみ」)。購入・サルベージのような状態変更操作は持たない
- 走行画面からD0x詳細への遷移は、通常の図鑑一覧経由の遷移と**同一コンポーネント**を再利用する(初回か既知かはpropsで分岐、5節)

## 5. 検死レポート統合レイアウト(図鑑D0x詳細画面)

art-spec §5.2「実験ノート/図鑑はN6地に暗色文字の『紙』様式」を踏襲し、`docs/phase2-ui-shop-plan.md`のショップ画面と同じ紙UIパターンに統一する。

D0x詳細画面(1画面、上から下へ):

1. **見出し**: モードID+名称(例:「D04 リポ炎上」)。未発見は本画面に到達しない(一覧側でシルエット止まり)
2. **リプレイ**: シード再現(spec §7.2)。既存`RaceCanvas`/`MotorCanvas`相当の再生専用ビューを小型で埋め込む(操作不可、再生/一時停止のみ)
3. **検死レポート(物理ログ)**: engineが記録した`causeLog`(電流・温度・回転数・タイムスタンプ、spec §7.1)を表形式で列挙。数値は計測パネルと同一の実単位表記(art-spec §5.5の店舗と同じ「実測値の生表示」原則)。**原因の解釈文は書かない**(「モーターが壊れました」等の説明文を追加しない。生ログの提示に留める——難易度哲学「答えを教えない」spec §1.2)
   - **温度表示(Suu_mot3 v1レビュー条件1、v2追加)**: `temperature`欄は実温度(モーター/電池等、engine契約が指す対象の実測温度)のみを表示する。他の物理量(電流・回転数等)を温度の代理値として換算・表示しない。engine契約が当該破壊イベントで温度を取得できない(未計測)場合は、数値の代わりに「未計測」と明記し、0や推定値で埋めない
4. **初回発見報酬(初回のみ)**: 報酬額+「はじめて記録した破壊」である旨を明記。**Suu_mot3 v1レビュー条件4(v2追加)**: 報酬額はPhase5の経済結線まで仮値であり、実際の受領処理(所持金への加算等)もPhase3時点では未結線であることをこのブロック内に明示表示する(`docs/phase2-ui-shop-plan.md`の「試遊用の仮データ」表示と同じ扱い、8節に文言例)。二回目以降はこのブロック自体を表示しない(spec §7.2)
5. **実験ノートへの導線**: 「実験ノートで比較を見る」ボタン(同一レシピの過去走行比較、7節)。検死レポート本体を実験ノート側に複製しない
6. **戻る**: 図鑑一覧またはガレージへ戻る操作(遷移元に応じて分岐、6節)

D0x一覧画面:

- グリッド表示(9マス、D01〜D09。D10はPhase4スコープ外として本一覧に含めない)
- 未発見: シルエット+「???」(spec §7.2の網羅率と同じ「欲望の可視化」、art-spec §5.5未解禁ティア表示と同一意匠を転用)
- 発見済み: モード名+小サムネイル(演出の代表1コマ、静止画)

## 6. 破壊発生時の遷移フロー

Suu方針(`docs/phase3-suu-draft-review.md` 29行)を具体化する。

1. **破壊発生**: engineが`DestructionState`終端(該当D0xの破壊完了)を通知した時点で、走行を物理状態に従って終了/停止する(engine側の停止判定に従うのみで、UI側が独自のタイムアウトで停止を判断しない)
2. **症状表示の保持**: 走行画面はその場で停止し、破壊演出(パーティクル、art-spec §6)と症状(D0xごとの視覚差分、spec §7.1表)を表示したまま**自動では遷移しない**。時間制の自動遷移は不採用(Suu方針)
3. **決定操作**: プレイヤー操作「検死レポートへ」(仮ボタン文言、8節)を押すまで停止画面を維持する。Escapeやタイムアウトでの読み飛ばしは設けない(生の結果を必ず見せる、spec §1.2の難易度哲学と整合)
4. **図鑑詳細画面への遷移**: 「検死レポートへ」操作後、当該D0xの図鑑詳細画面(5節)へ遷移する。初回発見時は報酬ブロックを表示し、既知の場合は通常のD0x詳細と同一画面を報酬ブロックなしで表示する
5. **ガレージへ戻る**: 図鑑詳細画面での確認操作後は、既定フロー(現行の走行後リザルト→ガレージ遷移と同じ導線)でガレージへ戻る。図鑑一覧経由でこの画面を開いた場合は、確認操作は図鑑一覧へ戻す(遷移元を状態として保持する必要がある、10節)

破壊がリタイア(コースアウト・走行失敗)ではなく**通常完走**の場合の既存リザルト画面フローには影響しない(本書は破壊発生時のみを対象とする)。

## 7. 実験ノートとの導線(三段開示・段階2)

spec §7.3段階2「実験ノートのA/B比較を拡張し、同一レシピの過去走行と自動照合して『同一構成で記録が3%低下』という事実だけを提示する」に対応する導線のみを扱う(自動差分検知ロジック自体はengine/store側の実装であり本書のスコープ外)。

- D0x詳細画面(5節)の「実験ノートで比較を見る」ボタンから、既存`ExperimentNotebook`を当該レシピでフィルタした状態で開く
- 実験ノート側に検死レポート(物理ログ)を複製表示しない(Suu方針、`docs/phase3-suu-draft-review.md` 21行「検死レポート本体は持たせません」)。実験ノートは事実(数値低下)の提示に専念する

## 10. Store所有境界・実装への留意点

- 図鑑の発見済みフラグ・報酬受領済み状態は永続化対象になる見込みが高いが(spec §7.2「網羅率を実績に接続」)、永続化スキーマの確定はPhase3のengine契約確定後に別途行う。本書はレイアウト・遷移設計のみを対象とし、`gameStore`の`persist`ミドルウェア`partialize`対象への追加可否は本書では決定しない
- **mode遷移元の保持方式(Suu_mot3 v1レビュー条件3、v2確定)**: 走行画面からD0x詳細画面への遷移時に「遷移元(走行画面/図鑑一覧)」を保持し、確認操作の戻り先を分岐させる状態(6節5)は、画面コンポーネント内のローカルstateへ散在させず、`gameStore`側の明示状態(例: `encyclopediaReturnTo: 'garage' | 'encyclopediaList'`のような単一フィールド)として持たせる案を優先する。理由は、同一のD0x詳細コンポーネントを複数の入口(走行画面直後/図鑑一覧経由)から再利用する設計(4節)であり、戻り先の分岐がローカルstateに散らばると再現性・テスト容易性が落ちるため。具体的なフィールド名・型は実装時にFableへ確認する
- `src/materials/`・`src/engine/`は変更しない(alice領域、越境しない)

## 11. テスト方針(実装時)

- 図鑑一覧: 未発見/発見済みの表示分岐(シルエット vs サムネイル)のテスト
- D0x詳細画面: 初回(報酬ブロックあり)/二回目以降(報酬ブロックなし)の表示分岐テスト

- 遷移元による戻り先分岐(走行画面経由→ガレージ、図鑑一覧経由→図鑑一覧)のテスト
- キーボード操作(Tab/Enter/Space)での一連の遷移が完走できることのテスト
