# Cursor確認依頼：巻いた後に買い足して、もう一度遊べるか

作成：Suu_mot3 / 2026-09-05。対象読者は画面操作を行うCursorデバッガー。§1〜3を順に実施し、§4の形式で報告してください。§5は確認終了後に人間へ渡す案内です。

目的は通常の反復操作の確認です。面白さ・音の合否は人間が判断します。この手順はソースから作成したもので、画面操作での通過はまだ確認していません。

## 1. 指定版と新しいテスト用セッションを使う

- リポジトリ：`https://github.com/SuuAlice/motor-game-v3`
- 専用ブランチ：`codex/p41c-restock-debug-handoff`
- 基点：`081e8994d14a71f54c0a651752d5f825acc35803`（受入済みP4-1C）
- 基点からの差分：`src/store/shopEconomy.ts`、`src/store/__tests__/shopEconomy.test.ts`、本書の計3ファイルだけ。
- 実行するcommit SHA：公開完了後の引渡しメッセージで指定する値。基点SHAを実行対象と取り違えないでください。指定SHAが届くまでは実行を開始しません。

P4-1Dの未完了変更は含みません。組み立て画面は8工程です。「巻線プロトタイプ(保存されません)」は古い比較試作なので、今回使いません。

新しいcloneで指定SHAに固定し、`git rev-parse HEAD`と`git status --short`を記録します。セットアップは次の順です。

```sh
node --version
npm --version
npm ci
npm run dev -- --host 127.0.0.1 --port 5176 --strictPort
```

起動URLは `http://127.0.0.1:5176/`。ポートが使用中なら他プロセスを停止せず、空いているポートへ変更して実行URLを報告してください。`npm ci`が失敗したら、そのエラーを報告して停止します。`--force`、lockfile編集、依存更新で回避しません。

新規のブラウザプロファイルまたは隔離コンテキストを使い、同じオリジンは1タブだけ開きます。人間のセーブは消さず、在庫・資金・記録をコンソールやlocalStorageから書き換えません。初期状態と異なる場合は、新しいテスト用セッションを用意してください。

主画面は390×844のタッチ対応viewportとします。実機スマホでない場合は、その点を報告します。PC表示は1280×800で巻線中の画面を1回確認するだけで十分です。

## 2. 完成後の小数在庫から銅線を買い足す

1. 「ガレージで車を組む」→「棚(在庫・サルベージ)」で銅線の初期残量と所持金を記録します。想定は銅線5 m・1000 Gです。まだ買い足しません。
2. ガレージへ戻り、「モーター工作台を開く」から組み立てへ進みます。銅線(標準)、線径0.4 mm、単線を選び、「この材料で巻き始める」を押します。
3. 張力50%、方向は順のまま「始動」。巻き数を見て80ターンで一時停止し、「巻き終える」を押します。張力を変えないため、操作パッドを不用意にドラッグしません。止め遅れた場合は実測ターン数を記録し、結果を80に書き換えません。
4. 「つぎへ」で進み、ワニスを塗って乾燥を待ちます。軸の固定は初期値のまま。やすりがけは「しっかり削る」6回で90%表示を確認し、スリット幅は1.5 mmへ設定します。台座と組み立ての設定は初期値を維持します。
5. 最終の「始動」工程で、画面のモーターを指またはポインターで素早く横へ弾きます。この操作で完成・線材消費・装備更新が行われる想定です。完成失敗の文言が出たら記録し、無理に後続へ進みません。長時間の無負荷運転は不要です。
6. 「モード選択」→「ガレージで車を組む」→棚で、完成後の銅線残量を撮影します。80ターンなら約1.481416228 mの想定です。画面が丸めて表示する場合は、見える値の精度で記録してください。
7. ガレージの「カタログ(店)」で同じ「銅線(標準)」をカートへ1単位追加して購入します。棚へ戻り、残量が購入前から1 m増え、所持金が100 G減ったことを確認します。「既存在庫の数量が有限の非負整数ではありません」で拒否されないことが今回の主確認です。
8. 同じタブを1回再読み込みし、棚へ戻って購入後の残量・所持金が維持されるか確認します。他タブ確認画面が出た場合は、その画面と待機時間を報告し、セーブを消して通過扱いにしません。

期待する結果は「完成で小数残量になる→同材を買い足せる→保存後も維持」です。直接の関数呼出しや自動テストだけを画面確認の代わりにしません。

## 3. 買い足した線材でもう一度組み、車体を走らせる

1. 同じセッションで工作台へ戻り、同じ銅線・0.4 mm・単線で30ターン巻きます。巻き数の常設表示と増加、始動・停止ボタンの操作を確認します。§2と同じ張力50%、順方向、ワニスあり、削り90%、スリット1.5 mmで完成させます。再入場時の設定は初期化されるため、必要な工程を省略しません。
2. ガレージの巻き数が30回に更新されることを確認し、「テスト走行」→「手で押してスタート」。走行状態へ進み、位置・速度等が更新されるかを観察します。約10秒以内の観察で十分です。走行中なら「走行を中止」して戻ります。固定タイムや勝敗は要求しません。
3. 操作不能、巻き数が見えない、表示枠の警告、アプリ由来のconsole.error/pageerrorがないかを記録します。画面の縦スクロール自体は失敗ではありません。車体が進まない・破損で停止する等があれば、状態と入力値を報告して止めます。成功させるためにレシピや物理を調整しません。

ここまで通れば、今回の操作確認を終了します。過去のD01〜D10試験、全素材・全入力方式の網羅、数値較正、音の確認を追加しません。

## 4. 結果は3判定と証拠を返す

```text
branch / 実行SHA:
実行URL / browser / OS / viewport（実機かエミュレーションか）:
起動時の問題:
A 完成後の小数在庫から同材購入: PASS / FAIL / 未確認
  完成ターン数、購入前後の残量・所持金:
B 再読み込み後も購入結果を維持: PASS / FAIL / 未確認
C 再組立30ターン→車体走行の操作: PASS / FAIL / 未確認
  巻き数・画面収まり・走行状態:
console.error / pageerror:
証拠画像の場所:
コード・commit・push・PR・配備を行っていないこと:
```

証拠は購入前後の棚、再組立中の巻き数、車体走行の計4枚程度で十分です。必要なら1枚追加し、長い動画の保存は必須にしません。スクリーンショットはリポジトリ外のartifactsへ保存してください。原因不明や手順の不一致はSuuへの報告で止め、コード・テスト・docsの修正、commit・push・PR・配備は行いません。ゲーム性の合否は付けません。

## 5. Cursor確認後、人間は自由に一度改良する

人間用には、この診断版とソースが一致するCloudflareの新しい固有Preview URLを別途渡します。古い `130ed9ff.motor-game-v3.pages.dev` は補充修正前なので、今回の修正版として案内しません。

入口は「ガレージで車を組む」→「モーター工作台を開く」。巻く→完成→テスト走行を一度試し、気になった点を変えて、もう一度作って走らせてください。固定の正解レシピ・勝敗は求めません。所感は「どこを変えたくなったか」「変えた結果を見て次も試したくなったか」で十分です。

この版は新しく作り直す方式です。一部分だけの巻き直し、厳密な修正前後比較、新しい整流子仕上げ工程は含みません。工作台へ入り直すと設定は初期値に戻り、素材は完成・破断時に消費されます。

用語：SHAはGitの版識別子、Previewは試遊用の配備先、オリジンはURLのプロトコル・ホスト・ポートの組です。不明点はこの結果報告を人間プロジェクトリード経由でSuuへ渡してください。
