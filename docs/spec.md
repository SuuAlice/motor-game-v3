# 仕様書:「回れ!手作りモーター」— 手作りDCモーター シミュレーションゲーム

Claude Code での実装を前提とした開発仕様書。

**v2 改訂内容**: 摩擦トルクの符号と静止摩擦の扱いを明確化 / 逆起電力(back-EMF)を導入 / 慣性モーメント J を巻き数から導出 / 整流子半径を定数として明記 / モード優先度とフェーズの矛盾を解消 / 軸ずれ振動をω²比例に変更 / 物理定数表を追加

## 1. コンセプト

中学理科の定番工作「エナメル線・爪楊枝・ダンボール・釘・クリップで作るDCモーター」を、ブラウザ上で追体験できる教育ゲームにする。

実物の工作で難しいポイント――

- 整流子の2本の線のすき間(ショートすると回らない)
- エナメルの削り具合(接触抵抗)
- ブラシの押し付け圧(強すぎると摩擦で止まる、弱すぎると通電しない)
- コイルの巻き数と磁石の強さ

――をそのままゲームのパラメータにし、**「なぜ回らないのか」を試行錯誤で学べる**ことを最大の価値とする。

### ターゲット
- 中学生(理科の電磁気分野の学習者)
- 実際に工作する前・した後の子どもと保護者
- 操作はマウス/タッチのみ。スマホ縦画面でも遊べること

## 2. ゲームモード

| モード | 内容 | 実装フェーズ |
|---|---|---|
| ④ サンドボックス | 全パラメータを自由にいじり、RPM・電流・トルクのグラフを観察 | **Phase 1(MVP・開発用を兼ねる)** |
| ② 調整チャレンジ | 完成済みモーターのパラメータを調整し、目標回転数(RPM)を達成 | Phase 2 |
| ① 組み立てモード | 手順に沿ってパーツを配置・加工する追体験チュートリアル | Phase 3 |
| ③ トラブル診断 | 「回らないモーター」が提示され、原因を特定して修理する | Phase 3 |

> **サンドボックスを最優先にする理由**: 物理エンジン完成直後に全パラメータを操作してグラフで挙動を確認できる画面がないと、エンジンのチューニング・デバッグが不可能なため。開発ツールを兼ねたMVPとして最初に作る。

### ① 組み立てモードの手順(実物の工程に対応)

1. **コイル巻き**: 釘にエナメル線を巻く(ドラッグ/連打で巻き数が増える。50〜100回が適正)
2. **軸の固定**: 爪楊枝と釘を十字に配置してテープ留め(位置ずれ=回転バランス悪化)
3. **整流子作り**:
   - ダンボール片を軸に刺す
   - 線の両端を紙やすりで削る(こすり操作。削り残し=接触不良)
   - 2本の線をダンボールに巻き、**すき間(スリット)を1〜2mmあけて配置**(スライダー操作。0mm=ショート)
4. **台座作り**: クリップ2本をU字軸受けに、2本をブラシに曲げる(プリセット選択でよい)
5. **組み立て**: 軸受けに軸を乗せ、磁石を釘の下に置き、電池を接続
6. **始動**: 画面をフリックして初速を与える → 物理シミュレーション開始

### 失敗パターン(実物と1対1対応させる)

| 症状 | 原因パラメータ | 実物での対応 |
|---|---|---|
| まったく回らない・電池が熱くなる | スリット幅 0(ショート) | すき間をあける |
| ピクッと動いて止まる | 削り残し(接触抵抗大) | やすりがけをやり直す |
| 回るがすぐ減速して止まる | ブラシ圧が強すぎ(摩擦) | 触れるか触れないかに調整 |
| 時々回るが不安定 | ブラシ圧が弱すぎ(接触不良) | 少しだけ押し当てる |
| 弱々しく回る | 巻き数不足/磁石が遠い | 巻き数を増やす・磁石を近づける |
| 回すと速度が頭打ちになる | 逆起電力(仕様、故障ではない) | ―(観察ポイントとして提示) |
| 高速で回すとガタガタ揺れて外れる | 軸の固定位置ずれ(振動はω²比例) | 十字の中心を合わせる |

## 3. 物理モデル(簡易だが本質を保つ)

フレームごと(固定タイムステップ dt = 1/120s、描画は60fps)に以下を数値積分する。

```
角運動方程式:  J·dω/dt = T_mag + T_fric + T_drag   (各トルクは符号込み)
角度更新:      θ += ω·dt
```

### 3.1 慣性モーメント J(巻き数に依存)

```
J = J_NAIL + K_J · coilTurns
```

- 釘+爪楊枝+整流子の基礎慣性 `J_NAIL` に、銅線1巻きあたりの寄与 `K_J` を加算する
- これにより「巻き数を増やす → トルクは増えるが立ち上がりが重くなる」というトレードオフが生まれる(調整チャレンジの深みの源泉)
- **J を定数にしてはならない**

### 3.2 磁気トルク(整流込み)

```
T_mag = K_T · B · i · N · sin(θ) × 整流符号
```

- N: 巻き数、B: 磁石強度、i: 電流
- **整流**: θ が半回転ごとに電流方向が反転
- **デッドゾーン**: スリット部分では電流ゼロ。角度範囲は整流子半径から換算する:

```
deadZoneRad = slitWidthMm / R_COMMUTATOR_MM
```

- `R_COMMUTATOR_MM` は物理定数表(3.7節)で定義する。**換算係数をコード内でその場ででっち上げないこと**

### 3.3 電流(逆起電力を含む)

```
e_back = K_E · N · B · ω                     // 逆起電力
i      = (V − e_back) / (R_coil + R_contact)  // 通電時のみ
i      = max(0, i)                            // 負値はクランプ(回生は扱わない)
```

- `R_coil = R_COIL_PER_TURN · coilTurns`(巻き数に比例)
- `R_contact` は「削り残し度」と「ブラシ圧」から算出(圧が弱いほど・削り残しが多いほど大)
- スリット幅 0 のときは短絡フラグ → 電池発熱アニメーション、トルクゼロ
- **逆起電力の意義**: 回転が上がるほど電流が自然に減り、無負荷回転数に収束する。「回転が速いほど電流計の針が下がる」= モーターは発電機でもあることの可視化。教材としての核であり、☆3効率評価(3.6節)の成立条件でもある
- デッドゾーン中は i = 0(e_back の計算自体は行うが電流は流れない)

### 3.4 摩擦・抵抗(符号に注意)

```
T_fric = −sign(ω) · MU_BRUSH · brushPressure   // クーロン摩擦: 運動と逆向き
T_drag = −C_DRAG · ω                            // 粘性抵抗
```

**静止摩擦とゼロクロスの扱い(実装上の必須要件)**:

1. `|ω| < OMEGA_EPS` かつ `|T_mag| ≤ MU_BRUSH · brushPressure` のとき、ω = 0 に固定し全トルクを打ち消す(静止摩擦に負けて動き出せない状態)
2. 積分ステップ内で ω の符号が反転する場合、そのフレームは ω = 0 でクランプする(摩擦トルクによる符号チャタリング防止)

> **警告**: 摩擦を `T_fric = μ·P` として無条件に減算すると、ω = 0 を通過した瞬間に摩擦が駆動力となって**モーターが勝手に逆回転する**バグになる。必ず上記の符号・クランプ処理を実装し、ユニットテストで検証すること(7節の受け入れ基準参照)。

### 3.5 確率的挙動・振動

- **接触不良(チャタリング)**: ブラシ圧が閾値未満のとき、フレームごとに確率で瞬断を発生させる
- **バランス不良**: 軸ずれによる振動は**回転数の2乗に比例**させる:

```
vibration = K_VIB · axisOffsetMm · ω²
```

  - ω に `vibration` に応じたノイズを加え、閾値超えで「軸が外れた」失敗演出
  - 低速では平気だが高速で暴れて外れる、という実物どおりの挙動を再現する(不釣り合いによる遠心力は ω² に比例するため)

### 3.6 スコアリング(調整チャレンジ)

- 目標RPM到達で☆1
- 安定持続(10秒間RPM変動±10%以内)で☆2
- 消費電流の少なさ(効率)で☆3
  - 逆起電力の導入により、電流は回転状態に依存する動的な値になる。同じ目標RPMでも「高電圧×強ブレーキ」より「適正電圧×低損失」の方が平均電流が小さくなり、☆1とは独立した評価軸として成立する

### 3.7 物理定数表(初期値。サンドボックスでのチューニングを前提とした出発点)

| 定数 | 初期値 | 単位 | 意味 |
|---|---|---|---|
| `J_NAIL` | 2.0e-6 | kg·m² | 釘+軸+整流子の基礎慣性 |
| `K_J` | 5.0e-9 | kg·m²/turn | 1巻きあたりの慣性寄与 |
| `K_T` | 1.0e-4 | N·m/(T·A·turn) | トルク定数 |
| `K_E` | 1.0e-4 | V·s/(T·turn·rad) | 逆起電力定数(K_T と同一値から開始) |
| `R_COIL_PER_TURN` | 0.02 | Ω/turn | エナメル線1巻きあたりの抵抗 |
| `R_COMMUTATOR_MM` | 5.0 | mm | 整流子(ダンボール片)の半径 |
| `MU_BRUSH` | 5.0e-5 | N·m(P=1時) | ブラシ摩擦係数 |
| `C_DRAG` | 1.0e-7 | N·m·s/rad | 粘性抵抗係数 |
| `OMEGA_EPS` | 0.5 | rad/s | 静止判定の閾値 |
| `K_VIB` | チューニング対象 | ― | 振動係数 |

- 定数は `engine/constants.ts` に一元管理し、マジックナンバーをコード中に散らさない
- 初期値は「適正パラメータ(巻き数80・スリット1.5mm・削り0.9・ブラシ圧0.3・ネオジム・距離10mm・3.0V)で数百〜千数百RPMに収束する」ことを目安にサンドボックスで調整する

### 調整可能パラメータ(データモデル)

```typescript
interface MotorConfig {
  coilTurns: number;        // 10–150
  slitWidthMm: number;      // 0–5
  sandingQuality: number;   // 0–1(削り具合)
  brushPressure: number;    // 0–1
  magnetStrength: number;   // 弱/中/強(フェライト/ネオジム)
  magnetDistanceMm: number; // 5–30
  batteryVoltage: 1.5 | 3.0;
  axisOffsetMm: number;     // 軸の固定ずれ 0–3
}

interface SimState {
  theta: number;      // rad
  omega: number;      // rad/s
  current: number;    // A
  backEmf: number;    // V(表示・グラフ用)
  shorted: boolean;
  running: boolean;
  rpm: number;        // 表示用(移動平均)
}
```

## 4. 画面・UI構成

```
[タイトル] → [モード選択]
   ├─ 組み立てモード: 工程ステップUI(横スワイプ) + 作業キャンバス
   ├─ 調整チャレンジ: メイン画面
   └─ サンドボックス: メイン画面 + グラフパネル

メイン画面レイアウト(縦画面基準):
┌─────────────────┐
│  モーター描画エリア (Canvas)   │ ← 釘・コイル・軸・整流子・ブラシ・磁石を側面図で描画
│  RPMメーター / 電流計         │
├─────────────────┤
│  パラメータパネル(スライダー群) │
│  [始動フリック] [リセット]      │
└─────────────────┘
```

- モーター描画は **Canvas 2D**。回転する釘+コイルを側面から見た2D表現(疑似3Dの奥行き縮尺で回転感を出す)
- 整流子の接触状態を色で可視化(通電=黄色ハイライト、瞬断=点滅、ショート=赤)
- 電流の流れをパーティクル(点の流れ)で表示 → 「電気の道」が直感的にわかる
- サンドボックスのグラフには RPM・電流に加えて**逆起電力**もプロットする(回転上昇とともに電流が減る関係が一目でわかる)
- 失敗時は原因のヒントを段階表示(すぐ答えを出さない。「電池が熱いよ…?」→「整流子を見てみよう」)

## 7. 実装フェーズ(Claude Codeへの発注単位)

### Phase 1: 物理エンジン + サンドボックス(MVP骨格)
1. `engine/constants.ts` と `engine/motorPhysics.ts` を実装し、ユニットテストを書く
   - 受け入れ基準:
     - 適正パラメータで定常回転(RPMが収束し、収束後の電流が始動時より小さい=逆起電力の効果)
     - スリット0でトルクゼロ(短絡フラグ)
     - ブラシ圧過大で停止し、**停止後に逆回転しない**(静止摩擦クランプの検証)
     - ω = 0 付近で符号チャタリングが起きない
     - 巻き数を増やすと定常RPMまでの到達時間が延びる(J の巻き数依存の検証)
2. Canvas描画 + スライダーUI + フリック始動
3. RPMメーター・電流表示 + サンドボックスのグラフパネル(RPM/電流/逆起電力)

### Phase 2: 調整チャレンジ
4. チャレンジ定義データと☆評価ロジック(☆3は平均消費電流で判定)
5. 失敗原因の判定(`failures.ts`)と段階ヒントUI
6. 進捗のlocalStorage保存

### Phase 3: 組み立てモード + 診断モード
7. 工程ステップUI(巻き数連打、やすりがけこすり操作、スリット調整)
8. 故障プリセットからの原因特定ゲーム

### Phase 4: 仕上げ
9. モーター音(Web Audio)、パーティクル演出、ショート時の発熱演出
10. PWA化(オフライン動作)、スマホ操作最適化

各フェーズ完了時に `npm run test && npm run build` が通ることをDoD(完了条件)とする。

# motor-game プロジェクト指針

- localStorage 以外の永続化・外部通信は行わない
