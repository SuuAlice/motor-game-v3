# 仕様書:「回れ!手作りモーター」— 手作りDCモーター シミュレーションゲーム

Claude Code での実装を前提とした開発仕様書。

**v2 改訂内容**: 摩擦トルクの符号と静止摩擦の扱いを明確化 / 逆起電力(back-EMF)を導入 / 慣性モーメント J を巻き数から導出 / 整流子半径を定数として明記 / モード優先度とフェーズの矛盾を解消 / 軸ずれ振動をω²比例に変更 / 物理定数表を追加

---

## 1. コンセプト

中学理科の定番工作「エナメル線・爪楊枝・ダンボール・釘・クリップで作るDCモーター」を、ブラウザ上で追体験できる教育ゲームにする。

実物の工作で難しいポイント――

- 整流子の2本の線のすき間(ショートすると回らない)
- エナメルの削り具合(接触抵抗)
- ブラシの押し付け圧(強すぎると摩擦で止まる、弱すぎると通電しない)
- コイルの巻き数と磁石の強さ

――をそのままゲームのパラメータにし、**「なぜ回らないのか」を試行錯誤で学べる**ことを最大の価値とする。

### ターゲット
- 中学生(理科の電磁気分野の学習者)
- 実際に工作する前・した後の子どもと保護者
- 操作はマウス/タッチのみ。スマホ縦画面でも遊べること

## 2. ゲームモード

| モード | 内容 | 実装フェーズ |
|---|---|---|
| ④ サンドボックス | 全パラメータを自由にいじり、RPM・電流・トルクのグラフを観察 | **Phase 1(MVP・開発用を兼ねる)** |
| ② 調整チャレンジ | 完成済みモーターのパラメータを調整し、目標回転数(RPM)を達成 | Phase 2 |
| ① 組み立てモード | 手順に沿ってパーツを配置・加工する追体験チュートリアル | Phase 3 |
| ③ トラブル診断 | 「回らないモーター」が提示され、原因を特定して修理する | Phase 3 |

> **サンドボックスを最優先にする理由**: 物理エンジン完成直後に全パラメータを操作してグラフで挙動を確認できる画面がないと、エンジンのチューニング・デバッグが不可能なため。開発ツールを兼ねたMVPとして最初に作る。

### ① 組み立てモードの手順(実物の工程に対応)

1. **コイル巻き**: 釘にエナメル線を巻く(ドラッグ/連打で巻き数が増える。50〜100回が適正)
2. **軸の固定**: 爪楊枝と釘を十字に配置してテープ留め(位置ずれ=回転バランス悪化)
3. **整流子作り**:
   - ダンボール片を軸に刺す
   - 線の両端を紙やすりで削る(こすり操作。削り残し=接触不良)
   - 2本の線をダンボールに巻き、**すき間(スリット)を1〜2mmあけて配置**(スライダー操作。0mm=ショート)
4. **台座作り**: クリップ2本をU字軸受けに、2本をブラシに曲げる(プリセット選択でよい)
5. **組み立て**: 軸受けに軸を乗せ、磁石を釘の下に置き、電池を接続
6. **始動**: 画面をフリックして初速を与える → 物理シミュレーション開始

### 失敗パターン(実物と1対1対応させる)

| 症状 | 原因パラメータ | 実物での対応 |
|---|---|---|
| まったく回らない・電池が熱くなる | スリット幅 0(ショート) | すき間をあける |
| ピクッと動いて止まる | 削り残し(接触抵抗大) | やすりがけをやり直す |
| 回るがすぐ減速して止まる | ブラシ圧が強すぎ(摩擦) | 触れるか触れないかに調整 |
| 時々回るが不安定 | ブラシ圧が弱すぎ(接触不良) | 少しだけ押し当てる |
| 弱々しく回る | 巻き数不足/磁石が遠い | 巻き数を増やす・磁石を近づける |
| 回すと速度が頭打ちになる | 逆起電力(仕様、故障ではない) | ―(観察ポイントとして提示) |
| 高速で回すとガタガタ揺れて外れる | 軸の固定位置ずれ(振動はω²比例) | 十字の中心を合わせる |

## 3. 物理モデル(簡易だが本質を保つ)

フレームごと(固定タイムステップ dt = 1/120s、描画は60fps)に以下を数値積分する。

```
角運動方程式:  J·dω/dt = T_mag + T_fric + T_drag   (各トルクは符号込み)
角度更新:      θ += ω·dt
```

### 3.1 慣性モーメント J(巻き数に依存)

```
J = J_NAIL + K_J · coilTurns
```

- 釘+爪楊枝+整流子の基礎慣性 `J_NAIL` に、銅線1巻きあたりの寄与 `K_J` を加算する
- 巻き数は「トルクと回転数のトレードオフ」を決める(増やすと始動トルク↑・無負荷回転数↓、§3.3の逆起電力とR_coilの巻き数依存による)。Jの巻き数依存は実装するが、`R_coil`・`e_back`とも巻き数に比例して増加するため、逆起電力が支配的な領域(適正パラメータ付近)ではJの増分が収束時間に与える影響は電磁制動(逆起電力による減速)に隠れて表に出ない。**J依存の効果は、同一トルク条件下でのΔωという単体プロパティとして検証する**(§7参照)。「巻き数を増やす→立ち上がりが重くなる」という単純な言い方はv2で誤りと判明したため撤回する
- **J を定数にしてはならない**

### 3.2 磁気トルク(整流込み)

```
T_mag = K_T · B · i · N · sin(θ) × 整流符号
```

- N: 巻き数、B: 磁石強度、i: 電流
- **整流**: θ が半回転ごとに電流方向が反転
- **デッドゾーン**: スリット部分では電流ゼロ。角度範囲は整流子半径から換算する:

```
deadZoneRad = slitWidthMm / R_COMMUTATOR_MM
```

- `R_COMMUTATOR_MM` は物理定数表(3.7節)で定義する。**換算係数をコード内でその場ででっち上げないこと**

### 3.3 電流(逆起電力を含む)

```
s      = 整流符号(3.2節)                        // 半回転ごとに ±1 反転
e_back = K_E · B · N · ω · sin(θ) · s            // 逆起電力(T_mag と同じ sin(θ)・整流符号を掛ける)
i      = (V − e_back) / (R_coil + R_contact)     // 通電時のみ
i      = max(0, i)                               // 負値はクランプ(回生は扱わない)
```

- `e_back` は `T_mag`(3.2節)と同じ `sin(θ)` と整流符号 `s` を掛ける。これは `T_mag·ω = e_back·i`(K_T = K_E のとき厳密に成立)というエネルギー整合性を満たすために必須で、`sin(θ)`・整流符号を省いた単純な `e_back = K_E·N·B·ω` は誤り(v2での修正点)
- `B`(磁束密度)は 3.7.1節の式で `magnetStrength` と `magnetDistanceMm` から算出し、`T_mag` と `e_back` の両方で必ず同一の算出関数を使うこと
- `R_coil = R_COIL_PER_TURN · coilTurns`(巻き数に比例)
- `R_contact` は「削り残し度」と「ブラシ圧」から算出(圧が弱いほど・削り残しが多いほど大)
- スリット幅 0 のときは短絡フラグ → 電池発熱アニメーション、トルクゼロ
- **逆起電力の意義**: 回転が上がるほど電流が自然に減り、無負荷回転数に収束する。「回転が速いほど電流計の針が下がる」= モーターは発電機でもあることの可視化。教材としての核であり、☆3効率評価(3.6節)の成立条件でもある
- デッドゾーン中は i = 0(e_back の計算自体は行うが電流は流れない)。デッドゾーンは θ ≈ 0, π 付近にあるため `sin(θ) ≈ 0` となり、e_back も自然にゼロへ近づく(整流の切り替わりと逆起電力のゼロ点が一致する)

### 3.4 摩擦・抵抗(符号に注意)

```
T_fric = −sign(ω) · MU_BRUSH · brushPressure   // クーロン摩擦: 運動と逆向き
T_drag = −C_DRAG · ω                            // 粘性抵抗
```

**静止摩擦とゼロクロスの扱い(実装上の必須要件)**:

1. `|ω| < OMEGA_EPS` かつ `|T_mag| ≤ MU_BRUSH · brushPressure` のとき、ω = 0 に固定し全トルクを打ち消す(静止摩擦に負けて動き出せない状態)
2. 積分ステップ内で ω の符号が反転する場合、そのフレームは ω = 0 でクランプする(摩擦トルクによる符号チャタリング防止)

> **警告**: 摩擦を `T_fric = μ·P` として無条件に減算すると、ω = 0 を通過した瞬間に摩擦が駆動力となって**モーターが勝手に逆回転する**バグになる。必ず上記の符号・クランプ処理を実装し、ユニットテストで検証すること(7節の受け入れ基準参照)。

### 3.5 確率的挙動・振動

- **接触不良(チャタリング)**: ブラシ圧が閾値未満のとき、フレームごとに確率で瞬断を発生させる
- **バランス不良**: 軸ずれによる振動は**回転数の2乗に比例**させる:

```
vibration = K_VIB · axisOffsetMm · ω²
```

  - ω に `vibration` に応じたノイズを加え、閾値超えで「軸が外れた」失敗演出
  - 低速では平気だが高速で暴れて外れる、という実物どおりの挙動を再現する(不釣り合いによる遠心力は ω² に比例するため)

### 3.6 スコアリング(調整チャレンジ)

- 目標RPM到達で☆1
- 安定持続(10秒間RPM変動±10%以内)で☆2
- 消費電流の少なさ(効率)で☆3
  - 逆起電力の導入により、電流は回転状態に依存する動的な値になる。同じ目標RPMでも「高電圧×強ブレーキ」より「適正電圧×低損失」の方が平均電流が小さくなり、☆1とは独立した評価軸として成立する

### 3.7 物理定数表(初期値。サンドボックスでのチューニングを前提とした出発点)

**設計目標(v2で追加。以下の定数はこの目標から逆算した値)**:

- 適正パラメータ(巻き数80・スリット1.5mm・削り0.9・ブラシ圧0.3・ネオジム・距離10mm・3.0V)で定常 約1000 RPM
- 収束後の平均電流が始動電流の40〜60%(逆起電力の効果が数値としてもUI上でも明確に見える程度)
- `brushPressure = 1.0` で停止、`brushPressure = 0.3` で正常回転(ブラシ圧過大による停止が実際に起こる)

初回実装時の値(`K_T = K_E = 1.0e-4`、`MU_BRUSH = 5.0e-5`、`C_DRAG = 1.0e-7`、`J_NAIL = 2.0e-6`、`K_J = 5.0e-9`)では、上記3つの設計目標を同時に満たすことができないことが実装時の検証で判明した(逆起電力を効かせるほど`MU_BRUSH`が相対的に無視できるほど小さくなり、ブラシ圧による停止が再現できなくなる)。以下は設計目標から逆算し、`sin(θ)×整流符号`の平均値 2/π での概算をもとに実装時の数値実験で微調整した値。

| 定数 | 初期値 | 単位 | 意味 |
|---|---|---|---|
| `J_NAIL` | 2.0e-5 | kg·m² | 釘+軸+整流子の基礎慣性 |
| `K_J` | 5.0e-8 | kg·m²/turn | 1巻きあたりの慣性寄与 |
| `K_T` | 2.0e-3 | N·m/(T·A·turn) | トルク定数 |
| `K_E` | 2.0e-3 | V·s/(T·turn·rad) | 逆起電力定数(K_T と同一値) |
| `R_COIL_PER_TURN` | 0.02 | Ω/turn | エナメル線1巻きあたりの抵抗 |
| `R_COMMUTATOR_MM` | 5.0 | mm | 整流子(ダンボール片)の半径 |
| `MU_BRUSH` | 2.5e-2 | N·m(P=1時) | ブラシ摩擦係数 |
| `C_DRAG` | 1.0e-6 | N·m·s/rad | 粘性抵抗係数 |
| `OMEGA_EPS` | 0.5 | rad/s | 静止判定の閾値 |
| `K_VIB` | チューニング対象 | ― | 振動係数 |

- 定数は `engine/constants.ts` に一元管理し、マジックナンバーをコード中に散らさない
- 初期値は上記の設計目標を満たすことをサンドボックスでのチューニングの出発点とする

### 3.7.1 磁束密度 B の算出(v2で追加)

`T_mag`(3.2節)と `e_back`(3.3節)は磁束密度 `B` を共有する。`B` は磁石の強さプリセットと磁石までの距離から次の1つの関数で算出し、両方の式で必ず同じ関数を呼び出すこと(別々に近似しない)。

```
B_material = B_MATERIAL_MIN + (B_MATERIAL_MAX − B_MATERIAL_MIN) · magnetStrength
B_floor    = B_material · B_FLOOR_RATIO
B(magnetStrength, magnetDistanceMm) =
    B_floor + (B_material − B_floor) · exp(−K_B_DISTANCE · (magnetDistanceMm − B_REF_DISTANCE_MM))
```

- `magnetStrength` は 0(フェライト相当)〜1(ネオジム相当)の連続値。UIの「弱/中/強」ボタンはこの範囲内の代表値(例: 0.2 / 0.5 / 0.9)を設定するプリセットとして扱う
- `B_REF_DISTANCE_MM` は磁石距離の可動域下限(5mm)に合わせ、そこでは距離減衰が効かず `B = B_material` となる
- 距離が離れるほど `R_contact`(3.3節)と同様の指数減衰+floorで `B` が下がる(0には収束させない。実物でも磁石を遠ざけただけで磁束密度が厳密にゼロになるわけではないため)

| 定数 | 初期値(暫定) | 単位 | 意味 |
|---|---|---|---|
| `B_MATERIAL_MIN` | 0.028 | T | フェライト相当(magnetStrength=0)の基準磁束密度 |
| `B_MATERIAL_MAX` | 0.14 | T | ネオジム相当(magnetStrength=1)の基準磁束密度 |
| `B_REF_DISTANCE_MM` | 5.0 | mm | 距離減衰の基準距離(可動域下限と一致) |
| `K_B_DISTANCE` | 0.04 | 1/mm | 距離による指数減衰係数 |
| `B_FLOOR_RATIO` | 0.15 | ―(0–1) | 遠距離での下限を `B_material` の何倍にするか |

これらは §3.7 冒頭の定数表とは別枠(v2で追加、磁束密度モデル専用)として `engine/constants.ts` に区分して定義する。初期値はサンドボックスでのチューニング対象とし、5–30mmの可動域全体で冒頭の目安RPMが破綻しないことを基準に決める。

## 4. 画面・UI構成

```
[タイトル] → [モード選択]
   ├─ 組み立てモード: 工程ステップUI(横スワイプ) + 作業キャンバス
   ├─ 調整チャレンジ: メイン画面
   └─ サンドボックス: メイン画面 + グラフパネル

メイン画面レイアウト(縦画面基準):
┌─────────────────┐
│  モーター描画エリア (Canvas)   │ ← 釘・コイル・軸・整流子・ブラシ・磁石を側面図で描画
│  RPMメーター / 電流計         │
├─────────────────┤
│  パラメータパネル(スライダー群) │
│  [始動フリック] [リセット]      │
└─────────────────┘
```

- モーター描画は **Canvas 2D**。回転する釘+コイルを側面から見た2D表現(疑似3Dの奥行き縮尺で回転感を出す)
- 整流子の接触状態を色で可視化(通電=黄色ハイライト、瞬断=点滅、ショート=赤)
- 電流の流れをパーティクル(点の流れ)で表示 → 「電気の道」が直感的にわかる
- サンドボックスのグラフには RPM・電流に加えて**逆起電力**もプロットする(回転上昇とともに電流が減る関係が一目でわかる)
- 失敗時は原因のヒントを段階表示(すぐ答えを出さない。「電池が熱いよ…?」→「整流子を見てみよう」)

## 5. 技術スタック

| 項目 | 選定 | 理由 |

## 7. 実装フェーズ(Claude Codeへの発注単位)

### Phase 1: 物理エンジン + サンドボックス(MVP骨格)
1. `engine/constants.ts` と `engine/motorPhysics.ts` を実装し、ユニットテストを書く
   - 受け入れ基準:
     - 適正パラメータで定常回転(RPMが収束し、収束後の平均電流が始動電流の40〜60%程度=逆起電力の効果、§3.7の設計目標)
     - スリット0でトルクゼロ(短絡フラグ)
     - `brushPressure = 1.0` で停止し、**停止後に逆回転しない**(静止摩擦クランプの検証)。`brushPressure = 0.3` では正常に回転する
     - ω = 0 付近で符号チャタリングが起きない
     - Jの巻き数依存(§3.1)を2種類のテストで検証する:
       - 単体プロパティ: 同一のθ・ω・トルク条件下で、coilTurnsが大きい(J が大きい)ほど1ステップあたりのΔωが小さい
       - 統合: 逆起電力支配域(適正パラメータ相当)では、coilTurnsを増やすほど定常RPMが単調に下がる(トルク型↔回転数型のトレードオフの検証。§3.1参照)

## 8. CLAUDE.md に書く内容(プロジェクト直下に配置)

```markdown
# motor-game プロジェクト指針

- 物理計算は src/engine/ の純関数のみで行う。ReactコンポーネントにdtループやNewton積分を書かない
- 物理定数は engine/constants.ts のみで定義する。マジックナンバー禁止
- 摩擦トルクは必ず −sign(ω) を掛け、ω=0付近は静止摩擦クランプで固定する(spec 3.4節)。無条件減算は逆回転バグになる
- 電流は逆起電力込みで計算する: i = (V − K_E·N·B·ω) / R、負値は0にクランプ(spec 3.3節)
- engine/ を変更したら必ず対応するテストを更新し npm run test を通す
- タイムステップは固定 1/120s。描画側で補間する
- パラメータの意味と適正範囲は spec の MotorConfig 表と物理定数表(3.7節)に従う
- UIテキストはすべて日本語。中学生が読める語彙で書く
- localStorage 以外の永続化・外部通信は行わない
```
