# Phase 4詳細計画 v4（P4-0実装解禁）: 15分の面白さ証明からガレージ深化へ

## 1. 目的

Phase 4の第一目的は、巻線物理を精密化することではない。次の15分前後の体験がゲームとして成立することを、最小の垂直スライスで証明することである。

```text
巻く → 固定ライバルと走る → 僅差で負ける
     → 事実を見る → 仮説を立てる → 一箇所だけ直す
     → 数値を見る前に違いを感じる → 勝つ → もう一度試したくなる
```

成功の中心は「高精度な物理値」ではなく、プレイヤーが自分の変更と挙動差を結びつけ、予想の的中を感じられることである。`docs/spec.md` §1.1の反目標に従い、より精密なパラメータシミュレータへ進むことをPhase 4の失敗として扱う。

## 2. Phase 4の分割

### 2.1 P4-0: 垂直スライス（今回、詳細計画を作る範囲）

- 巻線入力3案を、同一の巻線記録`{位置, 腕, 方向, 張力}`へ出力する比較試作として実装する。
- 固定素材・固定レシピ・固定seed・固定コース・固定ライバル1台で比較する。
- Phase 5のCPU、周回コース、経済較正、ボス、解禁を導入しない。
- 型紙は同じ巻線記録の複製と一区間の置換だけをセッション内で試す。
- 愛称・銘板・リザルト・履歴はセッション限定とし、save schemaへ追加しない。
- 任意の三走目でD01を確認する場合も、既存のD01物理・確定較正・破壊wrapperだけを使う。新しい物理式・閾値・較正軸は追加しない。
- 人間試遊の5条件で合否を決める。自動テスト数は代替にならない。

### 2.2 P4-1: ガレージ深化（P4-0通過後に詳細化する範囲）

P4-0で入力方式が確定するまで、P4-1は次の輪郭だけを固定し、詳細契約・数値・依存閉包を先取りしない。

- 確定した入力方式による巻線記録の本実装
- 記録から物理パラメータへの全写像
- 整流子の溝仕上げから接触品質・D05への接続
- 台座工程、釘本数、台紙素材
- 型紙の本実装と通常の素材消費
- 被膜ダメージ蓄積とD10

進角・電機子インダクタンス・アルニコ逆磁界減磁は将来枠であり、P4-1にも含めない。

## 3. P4-0で比較する入力3案

1. **生ドラッグ**: r2方式の比較対照。円運動を直接行い、ターンを記録する。
2. **半自動巻線治具**: ローターは一定の記録tickで回り、プレイヤーは横位置・独立した張力・正逆転を操作する。
3. **パターン設計+自動実行+要所修正**: 先に配置と張力の流れを作り、自動実行後に一部だけ手動で置換する。

三案のUIは異なってよいが、記録の型、値域、最大150ターン、検証、記録tick、同一操作列に対する決定論は共有する。入力方式ごとに物理式・記録型・勝敗条件を変えてはならない。

## 4. P4-0の合格条件

人間試遊で、次の5条件をすべて判定する。

1. 数値を見る前に改善を感じられる。
2. 初走後に自分なりの仮説を一つ言える。
3. 二走目で一箇所だけ直し、狙った方向へ変えられる。
4. 勝利後、促されずもう一度試したくなる。
5. 3回巻いても苦役と感じない。

入力方式の正式採用には、上記に加えて次を満たす。

- マウス、タッチ、キーボードのいずれでも記録できる。
- フレームレート差が記録値を変えない。
- 入力補助が4値の決定権を奪わない。
- 手癖が巻線の見た目へ残る。
- 30〜60秒で1本を完成できる。

## 5. 過剰設計防止の停止条件

次のいずれかが必要になった時点で実装計画を止め、人間承認またはarbiter裁定へ戻す。

- `src/engine/`の新しい物理式、状態変数、破壊閾値、較正値が必要になった。
- Phase 3のRunSnapshot、RunOutcome、保存schema、図鑑、在庫、原子的反映契約の変更が必要になった。
- Phase 5のCPUシステム、周回コース、経済、工房の永続化が必要になった。
- 3入力案ごとに別の巻線記録型または別の物理写像が必要になった。
- 「僅差負け→一箇所修正→勝利」を成立させるために、スクリプトタイム、ラバーバンド、表示だけの偽差分が必要になった。
- 色、フォント、内部解像度、色演算許可リスト、外部assetまたは依存packageの追加が必要になった。
- P4-0用の一時コードがP4-1で再利用できず、廃棄量が垂直スライスの最小性を超えると判明した。

## 8. 確定したP4-0境界

alice_mot3・brabit_mot3のread-only依存閉包調査、人間承認、arbiter条件付き承認を経て、次をP4-0の確定境界とする。

1. **Appのlocal表示状態から開くセッション限定の専用画面**とする。P4-0限定物は`src/p40/`へ隔離し、`gameStore.mode`、既存キャリア保存・在庫・図鑑・実験ノート・CourseMode進捗へ接続しない。
2. P4-0の物理写像は、実在する線量として`coilTurns=記録長`を保ち、方向一貫性を既存`effectiveTurnsRatio`へ、左右バランスを既存`axisOffsetMm`へ渡す最小2軸とする。P4-0のin-memory runに限る。P4-1では巻線由来の初期ratioとP3-3のD01走行中漸減ratioの積算契約を別途レビューする。
3. 位置と張力は記録・描画・比較へ残すが、P4-0では物理へ接続しない。分布、線長、占積、被膜損傷、D10はP4-1へ送る。
4. 固定ライバルは`TRACK_BY_ID`から得る検証済み`straight-10m`を既存`stepTrackRun`と固定seedでセッション開始時に生成した1台のtraceとする。保存へのoutcome適用、CPU判断、追従補正、ラバーバンドは持たない。推奨するD01案Aを採る限り、破壊wrapperも持ち込まない。
5. 3入力案は共通の意味操作列を同一記録へ変換できる最小比較試作とし、演出・音・保存を三重実装しない。
6. P4-0専用画面はV2 `CourseMode`のretro置換とは扱わない。legacy courseRun経路と到達不能ボタンの削除はPhase 5以降へ維持する。

## 9. 承認済み裁定と後続のexact承認

1. **P4-0のD01扱い**: 推奨案Aを採用済みとする。現行D01は`varnished=false`かつ高回転が原因であり、張力の連続量を入力に持たない。P4-0の任意三走目を合否必須から外し、張力→崩壊耐性の正式接続と同時にP4-1へ送る。張力を`varnished`へ読み替えず、P4-0で新しいD01物理・閾値・較正を追加しない。
2. **左右バランス写像の係数**: 既存`axisOffsetMm`へ入れる係数は、固定シナリオの有限sweepで候補を得た後、production反映前にexact値を再提示する。到達させるための新規物理・閾値変更は行わない。
3. **初走の僅差負け**: 固定初期型紙と固定ライバルの有限組合せから候補を選ぶ。走行中に相手性能を変える補正は不採用とする。人間の操作差で初走勝利になった場合は結果を偽らず、試遊票へ記録してシナリオ設計を見直す。

## 10. arbiter条件付き承認の確定反映

### P4-C1: 空・短記録の定義域

- 集計純関数は0〜150ターンの全域で有限値を返す。空記録では`coilTurns=0`、`effectiveTurnsRatio=1`とし、NaNを返さない。
- 1ターンでは`effectiveTurnsRatio=1`。2〜9ターンも集計・描画は受理するが、既存`coilTurns`受理範囲を満たさないため走行開始は拒否する。
- 0、1、2〜9ターンの境界テストを必須とし、NaN/InfinityのUI・runner流出を禁止する。

### P4-C2: RNG既定値経路の排除

- player/rivalの全stepは`createRunRng(seed)`で生成したRNGを明示的に渡す。
- `src/p40/sessionRunner.ts`にRNG引数必須のlocal wrapperを置き、P4-0から`stepTrackRun`を直接呼ばない。
- 構造テストでwrapper外の`stepTrackRun`直接呼出しと`Math.random`使用が0件であることを固定する。

### P4-C3: `effectiveTurnsRatio !== 1`の試作境界隔離

- `src/p40/**`と`src/materials/windingRecord.ts`から`recipeKey.ts`/`recipeCode.ts`をimportしない。
- P4-0 runnerから`computeRecipeKey`、`encodeRecipe`、`validateMaterialComposedBase`、`beginProductionRun`、`performApplyRunOutcome`を呼ばない。
- 上記を`src/p40/__tests__/boundaryAudit.test.ts`のexpected closureとして機械的に固定する。新しい物理式・較正・公開契約・保存経路は追加しない。

### 申し送り

- G3のexact候補には、`position`/`tension`の`1/256`量子化後に到達可能な離散`balanceErrorRatio`との対応を含める。
- P4-1の最初の論点として、巻線由来の初期`effectiveTurnsRatio`とD01走行中ratioの積算契約を、P3-3-Q5・Q12・Q14・P-Q10-A5と照合して別途裁定する。
- G7後の`spec.md`/`art-spec.md`同期は§9.1の入力装置割当だけを対象とし、巻線schema、D10、被膜、整流子、進角を先取りしない。
- P4-C1〜P4-C3反映後のarbiter再提出は不要。Suu_mot3が文書差分・hash・境界を照合し、G1へ進める。
