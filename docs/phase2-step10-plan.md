## 2. 現状認識(下調べ、engine非変更の範囲での読解)

### 2.1 (d) 整流モデル進角拡張の対象: `src/engine/commutator.ts`(26行)

現行実装は`getCommutationSign(theta)`(θ=π境界で符号反転)・`isInDeadZone(theta, slitWidthMm)`(θ=0/πの固定角±deadZoneRad/2をデッドゾーンとする)の2関数のみ。進角(θ=0/π以外の角度で整流点をオフセットする)は一切実装されていない。`motorPhysics.ts`はこの2関数を`computeElectricalState`(電流・逆起電力計算)内で直接呼び出しており(1箇所)、進角オフセットを導入する場合はこの呼び出し箇所・両関数のシグネチャ・関連する`motorPhysics.ts`側の定数(`R_COMMUTATOR_MM`等)との結合を洗い出す必要がある。

### 2.2 (e) 車両層の周回・横方向拡張の対象: `src/engine/vehiclePhysics.ts`(717行)・`trackPhysics.ts`(228行)

下調べの結果、想定より前提が進んでいることが判明した。`vehiclePhysics.ts`にはすでにカーブ・コースアウト判定が実装済みである: `TrackInputs.curveRadiusM`(区間の曲率半径、省略時は直線)を受け取り、`aLateral = v²/curveRadiusM`と保持限界`aLimit`(`tireGrip`・路面grip・重心高・モーター搭載オフセットから算出)を比較し、超過が`DERAIL_DETECTION_TIME_S`継続すると`status:'derailed'`へ遷移する。`trackPhysics.ts`の`TrackSegment`にも`curveRadiusM`(検証ロジック込み)が既に存在する。**訂正(Suu_mot3指摘)**: コード内コメント「Phase3新規」は同一履歴上の**旧V2開発フェーズ**由来の記述であり、V3のPhase3(本プロジェクトのフェーズ計画、`docs/spec.md` §12)で新規実装されたという意味ではない。この機能は**V2から凍結継承済みの既存ベースライン**である(CLAUDE.md「エンジン凍結方針」)。時系列を誤読させないよう、以下すべてこの理解で記述する。

したがって(e)の未実装部分は、スペック(spec §6.5)が要求する要素のうち次に絞られる可能性が高い(見積り作業でこの絞り込み自体を確定させる):
- **周回構造**(距離sがラップで巻き戻る、ラップ数管理): `trackPhysics.ts`の区間解決(`resolveSegmentAt`)が現状「線形区間の終端で`finished`」という直線コース前提になっていないか要精査
- **壁付きコース+ガイドローラーの中間状態(壁擦り)**: 現行は「保持限界超過が継続時間閾値に達すると即derail」の二値判定であり、spec §6.5が要求する「限界の80〜100%域での摩擦損+火花という中間状態(壁擦り)」は未実装と見られる
- **ガイドローラー(既存roller_materials)の写像**: `materialMapping.ts`は現状ローラー材質を一切消費しない(Step9報告書のcoverage gap)。(e)の見積り結果次第でこの写像実装の要否・規模が変わる

### 2.3 (d)(e)双方に共通する留意点

CLAUDE.mdの「エンジン凍結方針」は、(a)〜(e)の5点に限定してengine/の構造変更を許可する枠組みである。本Stepはこの5点のうち(d)(e)の**採否判断の材料を出す**段階であり、見積りが「小規模」と判定されても、実装着手には別途Fableレビュー+人間承認(CLAUDE.md「エンジンの計画は実装承認前にFableのレビューを経る」)が必要になる。

**(e)見積りで明示的に評価する5点(Suu_mot3指摘、必須)**:

- (a) spec §6.5が要求する連続的な曲率プロファイルκ(s)(距離sの関数)と、現行`TrackSegment.curveRadiusM`(区間ごとの符号なし半径、区間内一定)の表現差。区間分割の粒度でκ(s)をどこまで近似できるか、符号(左右カーブ)を持たない現行表現で十分か
- (b) ラップ数の定義・状態保持・周回終了判定を**どの層が持つか**(`trackPhysics.ts`の区間解決層か、`vehiclePhysics.ts`の状態か、あるいは呼び出し側の上位層か)。現行`resolveSegmentAt`が線形終端(`finished`)前提になっていないかを含む
- (c) 壁擦り(限界の80〜100%域の中間状態)の摩擦損・UIへの発火(火花演出等)に必要な観測値・イベント境界。engine側が返す値(既存`EnergyBreakdown`等の枠組みで表現できるか、新規フィールドが要るか)とUI側が消費するイベント境界を分けて評価する
- (d) ガイドローラー(roller_materials)の写像を`materialMapping.ts`側に閉じ、engineへは集計済みの値(保持力ボーナス等の単一スカラー)だけを渡せる設計にできるか。素材選択に応じた個別ロジックをengine/へ持ち込まずに済む見込みを評価する
- (e) 現行の保持限界`aLimit`が使う質量配分proxy(`centerOfMassHeightMm`・`motorMountOffsetMm`による減点)と、spec §6.5が要求する質量配分(電池・ボディ搭載位置がコーナー限界に効く)の要求との差分。既存proxyで十分か、新規パラメータの結合が要るか

### 11.1 (d) 進角拡張: **将来枠へ降格が相当(§2(d)の降格条項発動、Fable技術判定・人間最終承認待ち)**

選択肢A(commutationSignの切替点のみシフト、sinThetaはθの生値のまま)が物理的に正しく、選択肢Bは無効(進角ゼロと等価)。ただし選択肢Aを現行の**無誘導(記憶なし)電気モデル**へ導入しても、spec §9.2が要求する「高回転寄り/トルク寄りの特性シフト」は原理的に再現できない(ストールトルク・無負荷回転数が共にcos α倍される左右対称の劣化にしかならない)。実現には電機子インダクタンス(電流の一次遅れ、L/Rの時定数)の導入が必要で、これは`computeElectricalState`を記憶なしから状態持ちへ変える中核的な電気モデル拡張であり、全回帰・性質テストに波及する。3〜4節の「中規模」見積りはspec要求を満たす実装としては過小であり、実質的に大規模と再評価される。

spec §2(d)の降格条項(「大規模なら進角は将来枠へ降格する」)の発動が相当と判定され、(d)は将来枠(V3後期またはV3.x、インダクタンス導入+進角+MC4-新設を一体パッケージとして再見積り)へ降格することがFable技術判定として確定した(プロジェクトとしての最終決定は人間承認待ち)。Phase4は溝掘りジェスチャーを接触品質(チャタリング・D05)のみへ接続する既定フォールバックで実装する(spec §9.2が元々予定していたフォールバック)。
