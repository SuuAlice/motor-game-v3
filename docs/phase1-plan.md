## 1. 目的

V3のレトロ描画基盤を新設し、`docs/spec.md` §12および
`docs/art-spec.md`冒頭のPhase 1チェックリストを技術検証する。

Phase 1では次を確定または検証する。

- 内部解像度4案の比較
- 低解像度Canvasとニアレストネイバー整数拡大
- 共通48色パレットとRGB直値禁止
- 俯瞰斜め3/4走行ビュー
- 色演算許可リスト
- Mode 7演出層
- サンプルベースBGM 1曲とモーター音
- ミッドレンジスマホ相当での60fps成立性
- 初回ロード1MB未満の成立性

Phase 1のゲートは、人間による試遊での解像度承認と、無加工スクリーン
ショットを用いた美術レビュー運用の開始である。

## 2. 作業境界

- `src/engine/`は変更しない。
- 既存の`src/render/`・`src/components/`・`src/modes/`・`src/store/`・
  `src/data/`はV2凍結参考実装として保持し、変更・削除しない。
- V3基盤は`src/retro/`、検証画面は`src/retro-proto/`へ新設する。
- 検証画面は`retro-proto.html`から開き、既存V2の`index.html`と`App`は

- 新規依存は追加しない。必要になった時点で作業を停止し、別途承認を得る。
- フォント取得を含む実装作業は、人間承認済みのため開始してよい。

## 3. 現状

V2 UIはフル解像度CanvasとSVGを使用し、色のRGB直値が各所に存在する。
PixelMplusは`THIRD-PARTY-LICENSES`へライセンス文を収録済みだが、フォント
本体は未導入である。V2凍結基準は16ファイル・206テスト成功、dist総量
701,552 bytesである。

V3では、V2の「構成値から見た目を手続き生成する」設計思想だけを継承し、
描画・パレット・音源基盤は新設する。

## 4. 解像度比較

### 4.1 比較案

1. 320×180 単層
2. 480×270 単層
3. ワールド480×270 + UI 960×540 二層構成(本命案)
4. 640×360 単層

### 4.2 同一条件で比較する題材

- 150ターンの乱巻き軌跡
- ガレージ一枚絵
- 密な日本語を含む検死レポート画面

乱巻き軌跡は、仕様上の`{位置, 腕, 方向, 張力}`を持つ固定seedのダミー
記録から生成する。逆巻きを含めるが、逆巻きは色で区別しない。新しい
ターンを明色、古いターンを1段暗い色で描く。

### 4.3 評価基準

- 150ターンが塗りつぶしにならず「良い汚さ」として読めるか
- PixelMplus10/12の可読性
- 1画面に置ける情報量
- ガレージの描き込み密度
- スーファミ級の密度へ到達する制作負荷
- 各viewportで整数拡大が成立するか
- CSSピクセル基準とDPRを考慮した物理ピクセル基準で結果がどう変わるか

brabitは推奨案と非推奨理由を提出するが、解像度の最終決定は人間が行う。

### 4.4 検証viewport

CSS viewportの幅×高さとして次を検証する。

- スマホ縦: 360×640、390×844、414×896
- スマホ横: 640×360、844×390、896×414
- タブレット縦: 768×1024
- タブレット横: 1024×768
- デスクトップ: 1280×800、1920×1080

スマホ縦持ちでは内部レイアウトを転置し、横画面と同じパレット・部品描画を
使用する。

### 4.5 二層構成の未解決事項

ワールド倍率を`n`とするとUI倍率は`n / 2`であるため、`n`が奇数のとき
整数拡大規則と両立しない。

基盤には倍率計算と成立判定だけを実装し、緩和策を既定動作にしない。

- 偶数倍率へ1段落とす案は、試作内の実験分岐として比較する。
- UIを独立拡大して物理ピクセル一致を諦める案は仕様不適合として表示し、
  本番基盤には実装しない。
- 二層案自体の不採用を含め、試作結果を見て人間が判断する。
- Unit Aでは`devicePixelRatio`を入力とし、CSS viewportから物理ピクセル寸法を
  導出する方式も比較する。CSS基準方式との画質、表示寸法、処理負荷、二層倍率の
  成立可否を記録し、結果を`docs/art-spec.md` §2.1への反映案として提出する。

## 5. 描画基盤

### 5.1 整数拡大

- 全Canvasで`imageSmoothingEnabled = false`を設定する。
- 描画座標とスクロール量は整数ピクセルとする。
- viewportに収まる最大整数倍率を計算する。
- 余白はN0色のレターボックスで埋める。
- 二層構成では倍率の成立可否を明示的に返す。

### 5.2 パレット

Phase 1で検証・凍結候補とするのは、`docs/art-spec.md` §3の共通コア32色と
拡張16色、合計48色だけである。

- RGB直値は`src/retro/palette.ts`だけに置く。
- 会場サブパレット16色は会場実装時にSuu承認を得て追加する。
- 塗装バンクはマスターパレットと別枠とし、Phase 1では実装しない。
- `scripts/checkPaletteUsage.ts`で`src/retro/`と`src/retro-proto/`を検査する。
- 検査対象ディレクトリは引数で拡張可能にする。
- 違反検出テストは文字列fixtureを使い、違反ファイルを作業ツリーへ残さない。

### 5.3 俯瞰走行ビュー

5層パララックス検証は中止し、`docs/spec.md` §6.5/§8.4および
`docs/art-spec.md` §5.1.1に従う俯瞰斜め3/4見下ろしの走行ビューを試作する。

- カーブを含む壁つきのダミー周回コース
- 3/4視点の16方位ダミーマシン
- 自機追従の整数ピクセルスクロール
- 接地影
- G3高所オブジェクトによる遮蔽1点

壁とコーナーの可読性、および16方位スナップでコーナリングが滑らかに
見えるかを評価する。

### 5.4 色演算

許可する演算だけを`src/retro/colorOps/blend.ts`へ実装する。

- 加算合成: 火花、炎のコア、ヘッドライト、CRTにじみ
- 50%平均合成: 煙、霧、ガラス、夕景・夜景の空気遠近
- その他の半透明: 1px市松ディザ

発光・煙・夕景の3試作を、演算あり/なし、市松ディザと比較する。任意アルファ、
グラデーション、許可リスト外の演算は使わない。

### 5.5 Mode 7

家の見取り図を題材に、行単位のアフィン/透視ニアレストサンプリングによる
ズーム演出を1点作る。通常スプライトをMode 7層の上へ重ねられることも確認する。
走行ビューには使用しない。

## 6. フォント

対象は次のRegular 2ファイルだけとし、Boldは導入しない。

- `PixelMplus10-Regular.ttf`
- `PixelMplus12-Regular.ttf`

公式配布元は`https://github.com/itouhiro/PixelMplus`とする。人間の実装承認後に
取得し、次を記録する。

- 取得commitまたはreleaseタグ
- SHA-256
- 各ファイルのサイズ
- 配布元ライセンスと`THIRD-PARTY-LICENSES`の照合結果

CDNは使用せず、`public/fonts/pixelmplus/`へ同梱する。dist総量と、ブラウザが
初回表示で実際に要求・受信した転送量を分けて測定する。

Phase 1に限り、上記2ファイルはフルTTFのまま同梱してよい。容量の実測は行うが、
この時点では1MB超過だけを理由に停止せず、解像度確定後に容量予算の裁定を受ける。
裁定後に削減が必要とされた場合は、文字削減・サブセット化・新規ツール追加を
独断で行わず、候補、再生成性、追加依存の有無をまとめて報告する。

## 7. サンプルベース音源

外部サンプル、既存楽曲の耳コピ・アレンジ、実録音の既存素材は使わない。
すべてブラウザ標準のWeb Audio APIで内製する。

### 7.1 構成

- `OfflineAudioContext`で0.1〜2秒程度の短い楽器サンプルを生成
- 固定seedと保存済みパラメータによる再生成
- JSON譜面
- 最大8chの自作シーケンサ
- 自作インパルス応答と`ConvolverNode`による軽い残響1例
- モーター用短サンプルのRPM連動連続ピッチシフト

BGMは30秒の完成音声を単一サンプル化せず、短サンプル、エンベロープ、JSON譜面、
自作シーケンサで構成する。

### 7.2 再生成性

全パラメータ、固定seed、譜面JSON、IR設定をリポジトリへ保存する。生成画面の
ダウンロード機能だけに依存せず、生成条件を追跡可能にする。生成物は仮に
`src/retro/audio/generated/`へ配置する。

Web Audioのブラウザ間bit完全一致は前提にしない。タイミング計算、IR生成式、
RPMからピッチへの写像などの純関数を自動テストし、音響結果は対応ブラウザでの
実測と人間のPhase 1試聴レビューで評価する。

## 9. 性能・アクセシビリティ

### 9.1 性能測定

物理エンジンへ接続せず、ダミーデータで描画負荷だけを測る。React内へ物理用の
固定dtループを新設しない。

- スマホ基準: 縦390×844、横844×390
- デスクトップ基準: 1920×1080
- Chrome DevTools CPU 4倍スロットリング
- 2秒ウォームアップ後、10秒計測
- `requestAnimationFrame`間隔のp50、p95、p99、最大値
- 16.7ms超過フレーム数
- メモリ推移とGCの有無

最悪ケースは、俯瞰走行ビュー(壁つき周回コース、16方位マシン、自機追従整数
スクロール、接地影、G3高所オブジェクトによる遮蔽)、Mode 7、煙と発光、BGM、
RPM変化するモーター音を同時に動作させる。

### 9.2 アクセシビリティ

- 色だけで状態を示さず、形状も併用する。
- 試作タブと操作要素をキーボードで移動・確定できるようにする。
- フォーカスを視覚的に表示する。
- 縦持ち表示でも操作不能な要素を作らない。

## 11. Unit分割

### Unit A: 整数拡大・二層制約

- 対象: `integerScale.ts`、`layeredCanvasConstraint.ts`
- 成果物: CSS/物理ピクセル双方の最大整数倍率、レターボックス、二層成立判定の純関数、
  DPR別比較結果、`docs/art-spec.md` §2.1への反映提案
- テスト: 既知viewportとDPRから期待物理寸法・倍率・成立可否を検証
- 停止条件: 未承認の緩和策を既定動作へ入れる必要が生じた場合

### Unit B: パレット・検査

- 対象: `palette.ts`、`checkPaletteUsage.ts`
- 成果物: 共通48色、RGB直値検査関数とCLI
- テスト: 文字列fixtureによる違反検出
- 停止条件: 新規依存が必要な場合

### Unit C: フォント・容量

- 対象: PixelMplus Regular 2ファイル
- 成果物: 出所・hash・ライセンス記録、容量比較
- 停止条件: ライセンス・出所に問題がある場合。Phase 1中の容量超過は測定・報告し、
  解像度確定後の人間裁定までフルTTFを維持する

### Unit D: 試作entry・解像度比較

- 対象: `retro-proto.html`、試作シェル、4案×3題材
- 成果物: 試作entry基盤、4案×3題材の無加工スクリーンショットと比較表、
  §5.3の俯瞰走行ビュー試作(壁つき周回コース、16方位マシン、自機追従整数
  スクロール、接地影、G3高所オブジェクトによる遮蔽)
- 停止条件: 既存V2 UIまたは本番buildへの変更が必要な場合

### Unit E: 色演算

- 対象: `blend.ts`、色演算試作タブ
- 成果物: 発光・煙・夕景の比較
- 停止条件: 許可リスト外の演算が必要な場合

### Unit F: Mode 7

- 対象: `affineSampler.ts`、Mode 7試作タブ
- 成果物: 見取り図ズーム、通常スプライト重ね合わせ
- テスト: 座標写像の既知値テスト

### Unit G: 音源

- 対象: `src/retro/audio/`、音源試作タブ
- 成果物: 短サンプル、JSON譜面、8chシーケンサ、残響、モーター音
- 停止条件: 容量超過、新規依存、権利上の懸念が生じた場合

### Unit H: 性能測定・DoD

- 対象: `frameProbe.ts`、最悪ケース試作タブ
- 成果物: 性能・容量・アクセシビリティの結果と全ゲート資料
- 依存: Unit A〜G完了後

進行順は`A → B → C → D/E/F/G → H`とする。各Unit終了時にbrabitはSuuへ
成果物、テスト結果、実費、未完了事項を報告する。個別の追加着手承認は不要だが、
停止条件に該当した場合は次Unitへ進まない。

## 14. 停止・報告規則

次の場合は独断で回避せず、作業を停止してSuuへ報告する。

- `src/engine/`または既存V2 UIの変更が必要
- 新規依存、外部サービス、有料素材が必要
- フォントまたは音源に権利上の懸念がある
- 解像度確定後の容量裁定で削減が必要と判断された
- 仕様にない色、演算、解像度処理が必要
- 本番buildへ予期しない影響がある
- 意図しないファイル変更が発生した

完了・停止のいずれでも、brabitはagmsgでSuuへ、成果物、テスト結果、実費、
未完了事項または停止理由を自発的に報告する。
